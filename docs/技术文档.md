# DB Client — 技术文档

> Monorepo：`db-core`（纯连接/查询/元数据层）、`vscode-ext`（VS Code 扩展）、`server`（云同步后端）。
> 本文聚焦架构、SQL 补全引擎设计、连接生命周期与已实施的工程修复。
> 数据、订阅、组织 Workspace 与权限的后续设计以 [V3 实施规格](./v3/实施规格.md) 为准；本文不把当前 V2 运行时模型描述为目标架构。

## 1. 架构总览

```
packages/
├── db-core/     # 纯层：IConnection 适配器 + 方言策略 + 查询/元数据/数据/表/结构对比服务（无 vscode 依赖）
├── vscode-ext/  # 扩展层：命令、树视图、表单、webview 查询/设计/ER、i18n、云同步客户端、补全
└── server/      # Fastify + MySQL + JWT，云同步与账号服务
```

分层原则：

- **db-core** 不依赖 vscode，可独立测试；驱动适配（mysql2 / pg / sqlite3 CLI）与方言（标识符包裹、分页、元数据 SQL）内部收敛。
- **vscode-ext** 通过 `ConnectionManager` 持有 db-core 会话，命令/树/webview 是多套消费方。
- **server** 独立部署，提供注册/登录（JWT）与加密同步接口。

## 2. SQL 补全引擎（`vscode-ext/src/completion/sqlCompletionEngine.ts`）

设计为**纯函数、无 vscode 依赖**，供两处复用：

1. webview 查询面板后端（`result/tableQueryView.ts` 的 `completion` 消息）
2. `.sql` 编辑器 `SqlCompletionProvider`

### 2.1 上下文判定（`detectContext`）

基于光标前文本作**优先级正则匹配**的状态机，11 种上下文：

| 顺序 | 上下文 | 判定示例 | 触发位置 |
|---|---|---|---|
| 1 | `dot_column` | `u.` / `o.` | 表别名后限定列 |
| 2 | `after_table` | `FROM users `(带尾空格) | 表名完整后→子句关键字 |
| 3 | `from_table_typing` | `FROM ` / `FROM us` | 正在输入表名 |
| 4 | `order_clause` | `ORDER BY ` / `GROUP BY na` | 排序字段 |
| 5 | `where_operator` | `WHERE age ` | 字段后→比较操作符 |
| 6 | `where_value` | `WHERE age > ` / `name LIKE ` | 操作符后→值/函数 |
| 7 | `where_condition` | `WHERE ` / `AND age > 18 AND ` | 条件左侧（输入字段名） |
| 8 | `set_clause` | `UPDATE users SET ` | 更新列 |
| 9 | `select_clause` | `SELECT `（未到 FROM） | 投影列/函数 |
| 10 | `statement_start` | 空 / 分号后 | 语句起始 |
| 11 | `default` | 其他 | 兜底 |

设计要点：

- **优先级**：`dot_column` 用 `(\w+)\.\w*$` 先命中，避免与 `from_table_typing` 冲突。
- **表名完整 + 尾空格 → `after_table`**：`FROM users `（打了一个空格）从「继续提示表名」切到「提示 WHERE/ORDER/JOIN 等子句」。无尾空格时（光标紧贴表名）无法判定完整性，回落 `from_table_typing`，多打一个空格即切换。
- **where 三段式**：`where_operator`（字段后提示 `=`/`LIKE`/`IN`/`IS NULL` 等）→ `where_value`（操作符后提示函数/列/值/子查询）→ `where_condition`（`AND` 后继续输入字段）。`where_operator` 需在 `where_condition` 之前判定，避免 `\w*$` 吞掉尾空格。
- **`after_table` 不再混入语句关键字**（SELECT 等），只提示子句关键字 + 列。
- 正则用 `\w*$` 匹配当前输入词，交给前端做前缀过滤。

### 2.2 候选组合（`buildCandidates`）

每个上下文返回带类别的候选集：

```ts
type CompKind = 'keyword' | 'table' | 'column' | 'function' | 'operator';
interface CompletionCandidate { label: string; kind: CompKind }
```

- `select_clause` → 列 + 函数 + `DISTINCT/*/AS/FROM`
- `after_table` → 子句 + 语句关键字 + 列
- `from_table_typing` / `set_clause` → 表 / 列
- `dot_column` → 该表列（无列时回落函数）
- `where_condition` → 列 + 函数 + 运算符（AND/OR/NOT/IN/LIKE…）

**元数据（表/列）由调用方注入**，引擎不访问数据库 —— 保证纯函数可测。

### 2.3 前缀过滤（`filterByPrefix`）

大小写不敏感 `startsWith`。前端收到全量候选后按当前输入词过滤，减少往返。

### 2.4 双端接入差异

| 端 | 元数据来源 | 前缀过滤 | 类别映射 |
|---|---|---|---|
| webview 后端 | `MetadataService.getTables/getColumns`（无缓存） | 前端 `filterByPrefix` | 前端按 kind 着色 |
| `.sql` Provider | 同上（带 `tableCache/columnCache`） | VS Code 内建 | `CompletionItemKind` |

## 3. 连接生命周期

### 3.1 现状

`ConnectionManager.connect(conn)` 按 `conn.id` **幂等缓存**会话（`Map`），消费方包括：树中显式打开、查询/表预览/补全/EXPLAIN/单元格编辑。

实际消费方有两类生命周期：

- **显式打开**：`dbclient.openConnection` 显式 `connect` 并 `markExplicit`，用户手动关闭（`closeConnection`/`deleteConnection`/`refreshConnection`）前保持。
- **隐式打开**：查询视图/补全/预览触发的连接，随视图引用计数自动释放。

### 3.2 自动释放（本次修复）

- `TableQueryView` 维护静态 `connRefs: Map<connId, count>`，构造时 +1，`onDispose` 归零。
- 归零时若连接**非显式打开**则 `disposeConn`，否则保留（树中显示打开状态的连接不被查询面板误关）。
- 补全/查询共用同一会话，不重复建连。

### 3.3 会话有状态风险

MySQL 会话有状态（`USE db`、事务、会话变量、临时表）。同一视图/会话的查询通过**串行队列**（`execQueue`）按序执行，避免并发污染 `USE`/事务状态并防止取消句柄互相覆盖。

### 遗留（建议后续）

- **MySQL `typeCast` 全量字符串化**：`MysqlConnection.typeCast` 把所有非日期值 `buffer.toString()`，数值/布尔到上层都是字符串。F22 只在消费端用 `toBool` 归一，治本需改 `typeCast` 本身 —— 爆炸半径覆盖结果网格、导出、schema diff，需单独一轮 + 真实库回归。
- **PAT 认证**：已在 v2 整体废弃（服务端无 PatService、无 /api/pats、package.json 无 dbclient.pats）。
- **webhook 验签**：已用作用域 content-type parser 实现 `req.rawBody`，HMAC 验签可用（`route/webhook.ts:33-55`，有真 HMAC 测试）。
- **`requireFeature` 网络失败放行**：`catch { return true }` 让离线时付费功能全开。收紧会误拦离线的付费用户，属产品策略而非缺陷。
- **补全默认上下文仍查元数据**：无表需求的上下文可短路跳过 DB 请求。
- **错误静默**：`getTables/getColumns` 等 catch 返回 `[]`，元数据故障无可诊断提示（补全场景静默合理，暂保留）。
- **SQLite 批处理原子性欠 `-bail`**（本轮实测发现，优先级高）：`sqlite3` CLI 从 stdin 读 SQL 时默认**不在报错处中止**，因此 `BEGIN; A; B; 坏语句; COMMIT;` 会跳过错误继续执行到 `COMMIT`，把 A、B 提交掉。实测：不带 `-bail` 剩 2 行，带 `-bail` 剩 0 行。影响两处：
  - `BackupService.restore` 的 `singleStatement`（F33）只保证事务不被进程边界切断，不保证失败即全撤。
  - `importService.importRowsBatched` 的注释声称「保证事务原子性」，实际同样不成立 —— SQLite 导入中途失败会留下部分行。
  修法是给 `SQLite.query` 的 spawn 参数加 `-bail`，但该改动影响所有 SQLite 查询的错误行为（原本报错后继续执行剩余语句），需单独一轮 + 回归。
- **`SqliteConnection.query` 的 `event.emit('error')` 无监听者时抛 `ERR_UNHANDLED_ERROR`**（已修：callback 分支直接 return + `listenerCount` 守卫，`sqliteConnection.ts:75-82`）。
- **SQLite restore 菜单仍禁用**：两处菜单的 `dbclient.dbType != SQLITE` 门禁未解，待上面两项修完并端到端验证后再开。

## 5. 安全设计（现状）

### 5.1 凭据存储与同步边界

本地存储：连接密码、SSH 密码、SSH passphrase 三个敏感字段不写 `globalState`，而是存 VS Code `SecretStorage`（`ConnectionStore.SENSITIVE_FIELDS`）。`globalState` 里的连接记录已被 `sanitize` 剥离这些字段。

**云同步会上传凭据密文** —— 这一点需要明确，不要误读为「凭据不出本机」：

```
ConnectionStore.getSyncData()
  → materializeAsync(conn)      // 从 SecretStorage 取回 password/sshPassword/sshPassphrase
  → SyncManager.buildLocalPayload()
  → Encryption.encrypt(section, masterPassword)   // AES-256-GCM
  → POST /api/sync/:section     // server 只见密文
```

安全边界因此是**端到端加密**，而非「不上传」：

- 密钥由用户主密码经 PBKDF2-SHA256（600k 轮，旧数据回退 100k，迭代次数随 payload 记录以保证双向兼容）派生 32 字节。
- 每次加密使用随机 16 字节 salt 与随机 12 字节 IV，GCM 认证标签防篡改。
- 主密码不上传、服务端不掌握，服务端无法解密任何 section。
- 推论：**主密码遗失等于数据不可恢复**；服务端数据库泄露不直接泄露连接密码，但离线爆破主密码是残留风险，主密码强度即实际安全上限。

派生耗时约 0.4–0.6s/次，push 需对 5 个 section 各派生一次，故加解密走 `pbkdf2`（异步）而非 `pbkdf2Sync`，避免阻塞扩展主进程。

### 5.2 SQL 防护

- 标识符：`validateIdent` 白名单（Unicode 字母/数字 + `_$`，拒引号、分号、空格、反引号、注释符，长度 ≤64）+ 方言 `wrap` 包裹。
- 值：方言 `escapeValue`（MySQL `sqlstring`、PG `E''` 转义、SQLite `''` 双写）；LIKE 通配符经 `likeEscapeClause`，SQLite 显式带 `ESCAPE`。
- 执行：`confirmSqlExecution` 风险分级（无 WHERE 的 DELETE/UPDATE、DDL、生产环境标记二次确认），只读连接强制只读。

### 5.3 其他

- Webview CSP：`default-src 'none'`，script 走 `crypto.randomBytes` 生成的 nonce（不用 `Math.random`）。
- 内存：`QueryService.maxResultRows` 截断、查询超时 + `clearTimeout`。
- 审计：`AuditLogger` 记录查询执行流水到 `globalState`（上限 1000 条，SQL 截断 2000 字符），`Show Audit Log` 面板查看。
