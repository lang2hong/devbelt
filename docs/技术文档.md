# DB Client 技术文档

## 架构

```text
packages/
├── db-core/     # 纯 TypeScript 数据库核心
├── vscode-ext/  # VS Code 生命周期、UI 和本地状态
└── server/      # Fastify + MySQL 服务
```

- `db-core` 提供驱动适配、SQL 方言、连接、查询、元数据和数据操作，不依赖 VS Code 或服务端领域。
- `vscode-ext` 负责命令、树、webview、连接生命周期、凭据、本地状态和组织 Workspace。
- `server` 负责身份、个人权益、设备、组织授权、资源、同步状态和 MySQL 持久化。

## 扩展

扩展 activation 初始化连接存储、连接管理器、查询执行、结果视图、历史、审计、备份、数据库树、SQL 补全和组织 Workspace。

连接密码、SSH 密码和私钥口令存入 `SecretStorage`；普通全局状态只保存非敏感连接字段。组织连接模板使用独立的本地凭据映射，映射不上传服务端。

`ConnectionManager` 按连接 ID 缓存会话。有状态会话中的查询串行执行，避免事务、变量、当前数据库和取消句柄相互污染。

## 服务端

服务端采用 route -> service -> repository 分层。`createApp()` 负责配置 Fastify、MySQL pool、后台清理任务、依赖注入和路由注册。

所有组织请求从 URL 获取 `organizationId`，由服务端验证用户、组织、成员、权限、订阅和配额。客户端 Workspace 选择不参与授权。

`GET /health` 当前只返回进程状态，不检查数据库或外部依赖。

## 个人同步

服务端保存加密记录、公开签名材料、nonce 账本、幂等回执和状态版本，不保存连接明文、数据加密密钥、同步口令、恢复码或签名私钥。

扩展端已实现密码学、协议请求、状态存储、record 编解码、record 映射和 outbox。完整同步循环必须按以下顺序执行：

1. 对账服务端状态与 epoch。
2. 原样重放 outbox。
3. 推送已确认的本地变更。
4. 拉取固定 snapshot 的变更流并逐条应用。
5. 全部应用成功后持久化服务端 cursor。

具体协议和待办见[实施规格](实施规格.md)与[个人同步路线图](个人同步路线图.md)。
