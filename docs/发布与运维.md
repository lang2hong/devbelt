## 3. 服务端发布与回滚

### 3.1 发布顺序

1. 先发服务端（含 migration；`/health/ready` 在迁移完成前返回 503）。
2. 再发前端静态资源（旧前端仍兼容旧 API）。
3. 观察监控；异常按 §3.3 回滚。

### 3.2 部署脚本

```bash
bash apps/server/deploy.sh
```

脚本会：

- 构建 server bundle、db-ui、auth-ui、admin-ui；
- 备份服务器现有 `dist` 到 `backups/`；
- 通过 staging 目录原子替换；
- 写入 `.env` / `ai.env`；
- `systemctl restart devbelt-server`；
- 检查 `/health/ready` 与控制台静态资源。

### 3.3 回滚

```bash
ssh crewai "cd /usr/local/l2h/devbelt/server \
  && tar xzf backups/dist-<timestamp>.tar.gz \
  && sudo systemctl restart devbelt-server"
```

- 控制台静态资源从 `${CONSOLE_DIR}/backups/` 恢复。
- auth-ui / admin-ui 同理。
- 回滚只切换 HTML/服务端版本，不删除已发布 hash 静态文件，至少保留 7 天。
- 邮件入口至少保留两个前端版本，覆盖「发送 → 点击」窗口。

## 4. 运行手册

### 4.1 健康检查

| 端点 | 用途 | 语义 |
|---|---|---|
| `GET /health/live` | liveness | 进程存活，不连 DB，恒 200 |
| `GET /health/ready` | readiness | DB 连通 + schema 账本对齐 + mail 就绪；200/503 |

- 两者 `Cache-Control: no-store`、无 Cookie、响应体 < 500B、不泄露版本/库名/hostname。
- readiness DB 探活 2s 超时，DB 假死快速 503。
- 版本号走受控 `/api/console/version`（仅平台管理员）。

### 4.2 功能开关

- `browser-auth` / `mail-flow` / `sync-handoff` / `payment` 独立开关。
- 关闭时返回 `503 FEATURE_TEMPORARILY_DISABLED`，不回退弱安全链路。
- 现状：`payment` 已 opt-in 接线；其余为预留命名、未接线，不可当作紧急开关。
- 功能开关是**启动期快照**，改动需重启生效；不能当运行时 kill switch。

### 4.3 监控与告警

- 请求链路注入 `X-Request-ID`。
- 结构化 JSON 日志最少含 `requestId/timestamp/route/method/status/latencyMs/userId 摘要/errorCode`；不记录请求/响应原文、Cookie、Authorization、密码、E2EE 密钥、handoff/reset/CSRF/Idempotency 值。
- 指标按 `(route, method, status)` 聚合；告警只含 requestId、匿名聚合信息与错误码。
- 关键告警：
  - `/health/ready` 5min 失败；5xx > 1% 持续 3min；p95 超 SLO。
  - 登录/refresh 失败率突增；CSRF/Origin 拒绝突增。
  - 邮件流完成率下降；过期率 > 30%。
  - 同步 reset 失败率 > 5%；同用户重复失败 > 3 次/h。
  - DB 池 > 80%；p99 查询 > 1s 持续 5min，限流命中异常。

### 4.4 数据清理

| 表 | 动作 | 保留/触发 |
|---|---|---|
| `refresh_tokens` | DELETE | 终结后 7 天 |
| `email_verification_tokens` / `personal_sync_reset_tokens` | DELETE | 终结后 24h |
| `personal_sync_mutations` | DELETE | 过 `expires_time` |
| `mail_flows` | DELETE | 过期/消费后 24h |
| `idempotency_receipts` | DELETE + 审计摘要 | 过 `expires_time` |
| `sync_reset_handoffs` | expire + prune | 过期 → expired；终态后 24h 删除 |

- 周期默认 1h；每表每轮 ≤ 1000 行；失败只记日志、下轮重试。
- 清理账号最小权限；`sync_reset_handoffs` 仅允许受控 `status`/`update_time` UPDATE。

### 4.5 安全事件响应

1. 关闭对应功能开关（若已接线）。
2. 撤销受影响 session / mail-flow / handoff ticket。
3. 保留审计与取证数据，不清理、不覆盖。
4. 发布状态页说明。
5. 根因、修复、复测、安全评审完成后再恢复。

### 4.6 备份与恢复演练

- 每日全量 + 至少每小时增量/日志备份；加密、跨故障域复制。
- 每季度执行隔离环境恢复演练；恢复环境不得连生产 SMTP / 支付 / 遥测。
- SLO：RPO ≤ 1h，RTO ≤ 4h；基础设施不满足时不得宣称该 SLO。

## 5. 支付上线附录

> 仅当启用真实支付时适用；功能规格见 `docs/工作包/P4-支付闭环.md`。

### 5.1 凭据配置

支付凭据全部通过环境变量注入，base64 编码 PEM，不入库、不入仓库、不落日志。每个渠道「凭据齐全 + 回调 URL 合法」才视为已配置；任一缺失则整渠道 fail-closed 未配置。

| 变量 | 渠道 | 说明 |
|---|---|---|
| `DEVBELT_DB_PAYMENT_CALLBACK_BASE_URL` | 两者 | HTTPS 裸 origin，回调 URL 前缀 |
| `DEVBELT_DB_WECHAT_MCH_ID` / `DEVBELT_DB_WECHAT_APP_ID` | wechat | 商户号 / appid |
| `DEVBELT_DB_WECHAT_MERCHANT_CERT_SERIAL` | wechat | 商户证书序列号 |
| `DEVBELT_DB_WECHAT_PLATFORM_CERT_SERIAL` | wechat | 平台证书序列号，回调验签绑定 |
| `DEVBELT_DB_WECHAT_PRIVATE_KEY_B64` | wechat | 商户私钥 PKCS8 PEM base64 |
| `DEVBELT_DB_WECHAT_PLATFORM_CERT_B64` | wechat | 平台证书 SPKI PEM base64 |
| `DEVBELT_DB_WECHAT_API_V3_KEY` | wechat | 恰好 32 字节 AES-256-GCM key |
| `DEVBELT_DB_ALIPAY_APP_ID` | alipay | 应用 appid |
| `DEVBELT_DB_ALIPAY_PRIVATE_KEY_B64` | alipay | 应用私钥 PKCS8 PEM base64 |
| `DEVBELT_DB_ALIPAY_PUBLIC_KEY_B64` | alipay | 支付宝公钥 SPKI PEM base64 |

- 上线顺序固定：配全凭据 → `DEVBELT_DB_FEATURE_PAYMENT=true` → 重启 → 沙箱人工验收。
- 仅配凭据未开开关：支付保持关闭，下单/回调返回 503 或路由未注册。

### 5.2 运营注意事项

- 关闭支付开关前先关闭外部支付意图（微信关单 / 支付宝关闭交易）；否则已发出的二维码/跳转仍可能被付款。
- 微信平台证书当前为静态单证书；轮换需更新 serial + cert 并重启，旧证书在途回调会失败，渠道会重试。
- 微信回调校验 `appid`/`mchid`，支付宝校验 `app_id`；不匹配按解析失败拒绝。
- 支付宝异步通知返回字面 `success`；微信 v3 返回 `{code:'SUCCESS'}`；重复/已处理回调同样确认以止重试。
- 支付宝 `notify_time` freshness ±5 分钟；渠道重试超窗时评估放宽窗口，不静默接受。
- 过期 pending 订单 sweep、多渠道重复付款退款、账单对账仍属生产门禁；未闭环前不得宣称支付生产可用。

## 7. P2 双设备验收（B6）

> 依据 `docs/工作包/P2-个人同步-v2.md` §B6。本文只给执行步骤，不改变规格；冲突处以上述工作包文档为准。

### 7.1 前置

- 两个 VS Code Profile（两台机器或同机两 Profile）：A、B，登录**同一账号**，各安装含同步的 VSIX。
- A 执行「初始化」（设同步主密码 SMP）→ B 执行「解锁」。
- 每步截图 + 扩展日志；失败项按编号登记，修复后重跑该项与相邻项。

### 7.2 验收矩阵

| # | 场景 | 关键步骤 | 期望 |
|---|---|---|---|
| 1 | 连接同步 | A 新建连接（含分组）→ 同步 | B 出现同名连接与分组；树一致 |
| 2 | 保存查询 / 查询文件夹 | A 建文件夹 + 查询 → 同步 | B 树结构一致，引用不断链 |
| 3 | 本机路径（needsConfig） | A 设 `dbPath`/证书路径 → 同步；B 补齐 | B 保留本机覆盖，显示「需要配置」，不误用源值 |
| 4 | 分组级联 | A 删除分组 → 同步 | B 组内连接回落未分组，连接不丢 |
| 5 | 冲突 | A/B 并发改同实体 → 同步 | 出现冲突；Use Local / Use Remote / Cancel 各自收敛 |
| 6 | SMP 换钥 | A 换钥 → B 用新 SMP 解锁 | B 可解锁并拉到最新树 |
| 7 | 恢复码 | A 轮换恢复码 | 新码可用，旧码失效 |
| 8 | 销毁 | A 执行 destroy | 服务端进入新 epoch；A/B 行为符合规格 |
| 9 | 重置（reset） | 走 sync-reset handoff | token 一次性 + 限流；重置后收敛 |
| 10 | 跨窗口轮换 | 同机多窗口 refresh token | 不误吊销整族会话 |
| 11 | 锁定态零请求 | 未解锁/登出后观察网络 | activation/locked 不产生 sync API 请求 |
| 12 | 自动同步开关 | `devbelt.sync.autoSync` 开/关 | 开：本地变更（250ms debounce）与聚焦触发同步；关：仅显式命令触发 |

### 7.3 通过标准

- 12 项全 pass；任一项失败记录现象、日志、复现步骤，修复后重跑该项与相邻项。
- 结论回填到 `docs/工作包/P2-个人同步-v2.md` §B6 与本文 §6。

## 9. Migration 回滚

迁移是**前向**的：`migrations/index.ts` 只执行 `up`。结构/数据变更若需回滚，按下表执行手工 SQL。
执行前先备份（`mysqldump`），并在低峰期操作；回滚 SQL 一般**只针对对应迁移引入的增量**。

|---|---|---|

### 006_redis_engine

移除本迁移给 free/pro 的 `allowedDatabaseTypes` 追加的 `redis`：

```sql
UPDATE plan_feature_values v
  JOIN plans p ON p.id = v.plan_id
  JOIN plan_feature_defs d ON d.id = v.feature_def_id
   SET v.value_json = JSON_REMOVE(
         v.value_json,
         JSON_UNQUOTE(JSON_SEARCH(v.value_json, 'one', 'redis'))
       )
 WHERE d.feature_key = 'allowedDatabaseTypes'
   AND p.code IN ('free', 'pro')
   AND JSON_VALID(v.value_json)
   AND JSON_TYPE(v.value_json) = 'ARRAY'
   AND JSON_CONTAINS(v.value_json, JSON_QUOTE('redis'));
```

注意：`JSON_SEARCH(..., 'one', ...)` 只移除**首个** `redis`。若数组中可能有重复项，重复执行本 SQL 直到
`JSON_CONTAINS` 不再命中（幂等收敛）。

回滚后需同步回退迁移账本（否则再次部署会跳过 006）：

```sql
DELETE FROM schema_migrations WHERE version = '006_redis_engine';
```

> 账本表名以 `apps/server/src/repository/mysql/migrate.ts` 实际实现为准。
