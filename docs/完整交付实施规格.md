# 完整交付实施规格

本文是唯一交付输入。实施者按本文的工作包、契约和验收推进；当前代码是实现事实，Git 历史中的完整产品是能力基线。未提交工作树不等于已交付能力。

本交付为 greenfield：不迁移历史产品数据、不兼容历史 API、不保留已删除的分节同步运行时（见 commit `79475a8`、`67d0da2`）或 fallback。greenfield 不等于削减产品能力，历史已有的用户可见能力必须形成等价或更安全的可用闭环。

## 1. 交付目标与边界

发布版本同时交付：

1. VS Code 中 MySQL、PostgreSQL、SQLite 的连接、查询、数据编辑、结构设计、导入导出、SSH、备份和本地审计。
2. 注册、登录、设备管理和端到端加密个人连接同步，包含初始化、同步、冲突、换同步密码、恢复、销毁和丢失后重置。
3. 组织共享目录、连接模板和查询；浏览器中的组织设置、成员、邀请和订阅管理。
4. 微信、支付宝、人工收款的订单、订阅、席位和权益闭环；浏览器平台运营、审计和人工确认。

以下边界不可改变：

- 服务端现有认证、设备、个人权益、组织、邀请、资源和个人同步 route/service/repository/migration 是既定契约。新增能力只做直接追加，不重新建模既有领域。
- 个人空间按 `user_id` 计量，组织空间按 `organization_id` 计量。组织席位只授予该组织协作空间，绝不提升个人设备、连接或同步额度。
- 个人同步保持 E2E：服务端不能读取连接明文、DEK、同步口令、恢复码或签名私钥。组织资源不得包含数据库密码、SSH 密码、私钥、私钥口令、本机路径或个人同步材料。
- 平台角色和组织 `admin/member` 独立。平台角色不绕过组织作用域；前端隐藏项不能构成授权。
- 金额统一用 CNY 分的 `amount_minor BIGINT UNSIGNED`。支付商事件只能推进内部订单状态，不能直接修改套餐或权益。
- 不恢复已删除的 `packages/admin-ui`。新浏览器应用固定为 `packages/console-ui`；不引入独立管理会话，浏览器复用现有 auth/device 协议。

## 4. 插件完整交付规格

### 4.1 本地数据库能力

`package.json` 的 commands/views/menus/settings 是用户承诺清单。实施 P0 必须建立命令核查：每个 `dbclient.*` command 可追到 `registerCommand`，每个 view 在 `activate()` 创建或注册；无法实现的声明必须从 manifest、文案和 README 同时移除。

保留能力：连接与分组、MySQL/PostgreSQL/SQLite、SSH 隧道、SQL 编辑/执行/Explain/补全、表预览和编辑、表设计、DDL、索引/FK/触发器/例程/事件、ER、数据/模式对比、CSV/Excel/SQL 导入导出、备份恢复、连接导入导出、对象搜索、查询历史、本地审计、连接池和服务器仪表盘。

每项能力必须有 manifest command、注册 handler、最小测试和 Extension Development Host/VSIX smoke；涉及数据库的路径使用真实 MySQL/PostgreSQL/SQLite fixture，不能只验菜单可见。

### 4.2 个人同步运行时

正式 runtime 由 `src/sync/crypto/*` 与 `src/sync/e2e/*` 构成。`PersonalSyncClient` 只负责协议请求；`SyncEngine` 负责本地状态机，禁止在 webview 或 command 拼接协议请求。

固定编排：

1. 启动读取用户隔离的 snapshot、record map、pending outbox 和 SecretStorage DEK，调用 `GET /api/sync/state` 对账 epoch。
2. 无 state 时引导输入同步口令，生成 DEK/恢复码/envelope 后调用 `PUT /api/sync/init`。恢复码只显示一次，不能自动上传或写日志。
3. 个人连接变更先生成 CSPRNG recordId，预留 recordId-to-connectionId 映射，加密签名 mutation，完整落盘 outbox，再请求 `PUT/DELETE /api/sync/records/:recordId`。
4. 成功后先更新 map/state/version，再删除 outbox。超时、重启和 5xx 原样重放 mutationId、nonce、密文、digest、signature。
5. pull 顺序固定为：epoch 对账 -> 重放 outbox -> 推本地 mutation -> 分页 record feed -> 安全应用远端 -> 保存服务端确认 cursor。
6. 更高远端 version 碰到本地脏连接时，保留本地连接和 cursor，显示无秘密冲突 UI；不得静默覆盖、删除或无限重试。
7. change-key 只更新 SMP envelope；recover 轮换恢复材料；destroy/reset-after-loss 在远端确认后更新 snapshot、清 map/outbox/cursor、删除旧 DEK。本地中断保留可重放 cleanup 标记。
8. record 编码严格白名单：允许数据库密码、SSH 密码/passphrase；拒绝 SQLite 路径、SSH 私钥内容/路径、`sqliteCommand`、`connectionUrl`、`useConnectionString`、本地 ID、时间戳和组织凭据映射。组织连接永不进入个人 record map。

UI 必须提供初始化、解锁、立即同步、同步状态、冲突处理、改同步密码、恢复、销毁、丢失后重置。Argon2id 在 Worker 运行。不得显示或记录 DEK、SMP、恢复码、密文、nonce、signature 或完整错误 body。

### 4.3 个人权益与组织 Workspace

个人连接使用 `allowedDatabaseTypes`；无缓存时 fail-closed 为 Free `mysql/sqlite`。映射仅 `MYSQL -> mysql`、`PG -> postgresql`、`SQLITE -> sqlite`，未知引擎拒绝。门禁覆盖建连、save/test、导入和同步远端应用；删除不门禁。违规远端 record 逐条跳过并汇总，不整批失败。

组织 Workspace 与个人连接树、个人同步、本地持久化隔离。模板仅保存公共参数，用户名、密码、SSH 凭据只在本机 SecretStorage。登录态改变、401、成员移除、组织关闭或组织 scope 404 时清空组织内存 cache 与本机映射，不上传或迁移到个人同步。组织 admin 的“打开组织管理页”只打开 `/console/organizations/:organizationId`，不传 token、邮箱或凭据。

## 5. 商业与支付规格

### 5.1 主体、订阅、席位

- 个人订单/订阅属于 `user_id`，只购买 Pro；个人 Free 是降级目标。
- 组织订单/订阅属于 `organization_id`，购买 Team、续费或调整 seat；组织 Free 是新组织默认订阅。
- checkout、renewal、正向 change 均在支付成功后开启完整新周期并切换 snapshot。失败/取消保持旧订阅。
- 纯减席不调用支付商：目标不低于 active/invited 占用和 Team 最小 5 席，立即生效且不退款。
- `cancel_at_period_end=true` 到期降级 Free；全额退款成功立即降级。关闭组织撤销续费和 seat，不自动退款且不可恢复。

### 5.3 状态机与幂等

原订单：`pending_payment -> paid | canceled | failed`；全额退款后 `paid -> refunded`。退款订单独立为 `kind=refund,status=refund_pending`，只可变为 `refunded | refund_failed`。其他跳转返回 `409 PAYMENT_STATE_CONFLICT`。

| 动作 | 前置 | 原子结果 |
|---|---|---|
| checkout/change | active 可售 plan、周期 1/12、启用 provider、idempotency key | 锁主体订阅，生成不可预测 merchant order no，冻结 snapshot，插入 pending |
| 微信/支付宝支付意图 | pending order | 使用同一 merchant order no；网络未知保持 pending，重试不新建订单 |
| webhook paid | 原始请求验签且交易号/金额/CNY/订单匹配 | 认领事件，锁订单/订阅/seat，写 provider transaction，订单 paid，更新 snapshot/seat，写 audit |
| 人工收款 | `manual` pending order、platform admin step-up + reason | 同一 paid 事务；不得改金额、主体、plan 或 seat |
| 取消 | 当前订阅可取消 | 标记期末取消，不立即改权益 |
| 退款 | paid 原订单且无未终结退款、step-up + reason | 建等额 refund order；渠道退款或人工确认 |
| refund 成功 | 验签 callback 或人工确认 | 更新 refund/order，立即降级权益并撤销新增 seat，写 audit |

请求幂等边界是 `(subject,idempotency_key,request_digest)`：同 key/同 digest 返回原订单，不同 digest 为 `409 IDEMPOTENCY_KEY_REUSED`。callback 幂等边界是 `(provider,event_key)` 与 provider transaction 唯一键。验签失败、未知订单、金额/币种/商户单号不符绝不更新权益。

### 5.4 渠道适配器

`PaymentProvider` 统一实现 `createCheckout`、`verifyWebhook`、`parseEvent`、`requestRefund`；业务 service 不解析渠道私有 payload。

| Provider | 支付 | 回调/退款 | 禁止 |
|---|---|---|---|
| `wechat_pay` | 返回二维码/JSAPI/跳转白名单字段 | 原始 body + headers 验签；官方退款 | 密钥、证书、私钥入库；未配置密钥引用时发起 |
| `alipay` | 返回跳转/签名参数白名单 | 校验签名、out trade no、金额；官方退款 | 接受前端声称付款成功或跳过验签 |
| `manual` | 显示订单号和收款说明，`checkout=null` | 无 public webhook，Platform Admin 确认收款/退款 | 任意订单编辑为 paid/refunded |

密钥、证书和 webhook secret 仅在部署密钥管理系统；DB 保存 `key_reference`。原始 webhook body 不写普通日志；如需留痕，仅保存 event key、payload SHA-256、状态和无秘密 failure code。

## 6. 新增 API 契约

既有 API 不改名、不改所有权。新增 body 严格闭合；列表稳定排序且 cursor/limit 有上限；数字 ID JSON 字符串化。

#### 6.1 Checkout、变更与退款 DTO

```ts
type PaymentProvider = 'wechat_pay' | 'alipay' | 'manual';
type CheckoutRequest = {
  planCode: 'pro' | 'team';
  periodMonths: 1 | 12;
  provider: PaymentProvider;
  idempotencyKey: string; // 16..64 ASCII URL-safe characters
};
type OrganizationChangeRequest = {
  planCode?: 'team';
  seatDelta?: number; // non-zero integer; negative change omits provider/period/idempotencyKey
  periodMonths?: 1 | 12;
  provider?: PaymentProvider;
  idempotencyKey?: string;
};
type CheckoutResponse = {
  orderId: string;
  merchantOrderNo: string;
  provider: PaymentProvider;
  amountMinor: string;
  currency: 'CNY';
  expiresAt: string | null;
  checkout: null | Record<string, string>; // provider allowlist only, never secrets
};
type RefundRequest = { idempotencyKey: string; reason: string }; // reason 1..500
type ReauthRequest = { currentPassword: string };
```

`OrganizationChangeRequest` 的纯减席规则：`seatDelta < 0` 时只能带 `seatDelta`，不创建订单、不请求支付商、不可退款；其余 change 必须同时给 provider、periodMonths、idempotencyKey。所有 idempotency key 在主体范围内保存 24 小时，同 key 的 request digest 不同时必为冲突。`reason` 是所有平台写、人工确认、退款、角色变更的必填字段，禁止仅空白字符。

订单查询响应仅包含 `orderId,subjectType,subjectId,kind,provider,merchantOrderNo,amountMinor,currency,status,periodMonths,seatDelta,targetSeatLimit,effectiveTime,expiresTime,createTime`；不返回 webhook payload、签名、密钥引用以外的秘密或完整 plan snapshot。

| Method | Path | 调用者 | 请求/响应 |
|---|---|---|---|
| GET | `/api/personal/plans` | authenticated | 可见个人目录和订阅摘要 |
| POST | `/api/personal/subscription/checkout` | 本人 | `{planCode:'pro',periodMonths:1|12,provider,idempotencyKey}` -> checkout response |
| POST | `/api/personal/subscription/cancel` | 本人 | `{reason?}` -> 当前订阅摘要 |
| GET | `/api/organizations/:organizationId/subscription` | active member | 订阅、seat limit/used、目录摘要 |
| POST | `/api/organizations/:organizationId/subscription/checkout` | org admin | `{planCode:'team',periodMonths,provider,idempotencyKey}` -> checkout response |
| POST | `/api/organizations/:organizationId/subscription/change` | org admin | `{planCode?,seatDelta?,periodMonths?,provider?,idempotencyKey}` -> checkout 或立即摘要 |
| POST | `/api/organizations/:organizationId/subscription/cancel` | org admin | `{reason?}` -> 当前订阅摘要 |
| POST | `/api/webhooks/wechat_pay`、`/api/webhooks/alipay` | provider | 原始 payload -> provider ACK |

统一错误：`401 UNAUTHORIZED`、`403 USER_DISABLED`；组织不存在/关闭/非成员为 `404 ORGANIZATION_NOT_FOUND`，组织权限不足 `403 FORBIDDEN`；非平台管理员 `403 PLATFORM_ADMIN_REQUIRED`，step-up 失效 `403 PLATFORM_REAUTH_REQUIRED`，不可售套餐 `409 PLAN_NOT_PURCHASABLE`，seat 减少失败 `409 ORGANIZATION_SEAT_IN_USE`，支付冲突 `409 PAYMENT_STATE_CONFLICT`，非法事件 `400 PAYMENT_EVENT_INVALID`。

## 7. 浏览器控制台与发布

新增 `packages/console-ui`（Vue 3、TypeScript、Vite、Vue Router），base 固定 `/console/`。首次访问生成 256-bit `deviceKey`，固定 `devicePlatform='web'`；access token 仅内存，refresh token 仅 `sessionStorage`，绝不通过 URL/hash 传递。

Fastify 以固定版本 `@fastify/static` 托管 `/console/`；仅 `/console/*` 回落 `index.html`，`/api/*`、`/health` 和资源错误不回落。哈希资源长缓存，HTML `no-cache`。`deploy.sh` 先构建 console，再上传完整版本目录并原子切换；不得先删除线上唯一静态目录。

| 区域 | 路由 | 交付页面 |
|---|---|---|
| 公共 | `/console/login` | 登录、验证提示、会话失效 |
| 平台 | `/console/admin/users`、`/organizations` | 搜索分页、最小详情、禁用/恢复、设备/会话撤销 |
| 平台 | `/plans`、`/payment-providers`、`/orders` | 目录、渠道、订单、退款、人工确认 |
| 平台 | `/audit`、`/platform-admins` | 审计、平台角色；写操作均 step-up、reason、二次确认 |
| 组织 | `/console/organizations/:id`、`/settings`、`/members`、`/invitations`、`/resources` | 概览、订阅/seat、设置、成员、邀请、资源 |

平台 UI 永不显示密码、token/hash、同步密文/元数据、组织资源正文、个人连接、SecretStorage 映射或支付秘密。成员 email 仅由当前调用者为组织 admin 的专用 DTO 返回。

## 8. 审计、授权与事务

- 平台写、组织设置/成员/邀请变更、支付推进、退款、目录/渠道配置、平台角色变更写 append-only 审计。
- 成功审计和业务变更同事务；审计失败则业务回滚。已认证写操作业务失败以独立事务写失败审计；未认证扫描/普通越权只进安全日志。
- 组织写操作取得组织锁后重锁 actor active membership 并重算 permission，不信任 middleware 中旧 role/membership id。
- 平台写要求短时 step-up、原因和二次确认。不得撤销/禁用最后一个 active platform admin；不得禁用组织唯一 active admin，除非先完成管理员转移。
- checkout、callback、manual confirmation、refund 在同一事务锁订单、订阅、seat 和受影响 membership。支付成功/seat 分配不可拆成多个可见步骤。
- 日志和审计不含密码、token、完整 request/response、支付签名材料、资源正文、同步密文、nonce、recordId、mutationId、恢复码或私钥。

## 9. 工作包与完成定义

每包代码、测试、用户入口和文档一起完成；不得以存在 service、UI 或单测之一宣称交付。

| 包 | 范围 | 修改区域 | 完成条件 |
|---|---|---|---|
| P0 | 插件能力审计 | manifest、activation、commands、tests | 命令到 handler 自动核查；本地能力 VSIX smoke |
| P1 | 同步 runtime | `vscode-ext/src/sync/{crypto,e2e}`、activation、UI、tests | 双设备 E2E 收敛；断网/重启/outbox/冲突/epoch/恢复/销毁通过；无旧同步入口 |
| P2 | 组织管理闭环 | org Workspace、组织 DTO/API、console 组织页 | 资源/成员/邀请/cache/管理员跳转闭环；凭据隔离测试 |
| P3 | 商业和支付后端 | migrations `010-014`、commerce/payment routes/services/repos | 订单/订阅/seat、渠道验签替身、人工确认、幂等/乱序/退款测试 |
| P4 | 平台运营与审计 | `015`、admin API、console 平台页 | 授权、step-up、审计、目录/渠道/订单/人工运营闭环 |
| P5 | 同源发布 | console build、Fastify static、deploy、README | 深链接、缓存、API 隔离、原子发布和 rollback 演练 |

## 10. 验收矩阵

| 场景 | 自动化 | 人工验收 |
|---|---|---|
| 本地客户端 | db-core/extension tests、命令注册核查 | 安装 VSIX，连接三种数据库，执行查询、DDL、导入导出、SSH |
| 认证/设备 | auth route/service/MySQL integration | 注册、验证、两设备、撤销、改密后旧会话失效 |
| 个人同步 | crypto/protocol/runtime、真实 MySQL、双设备 E2E | create/update/delete、断网重启、冲突、恢复、reset |
| 组织协作 | route/service/concurrency/extension tests | 邀请、接受、角色变化、移除后清 cache；凭据仅本机 |
| 微信/支付宝 | adapter contract、验签 fixture、重复/乱序 callback integration | sandbox 支付；不符 callback 不改权益 |
| 人工收款/退款 | admin route/service integration | step-up+reason 确认；普通用户不能推进订单 |
| 订阅/seat | commerce transaction/concurrency | 加席、减席、占用拒绝、期末取消、退款降级 |
| 控制台 | component/router/API/browser E2E | 未登录/member/org admin/platform admin 路由隔离和深链接 |

真实 MySQL 只使用隔离 `MYSQL_TEST_URL`，数据库名必须含 `test` 或 `verify`。任何 skipped 的 MySQL、支付 sandbox 或 VSIX smoke 必须在交付报告明确，不得用单测替代。

## 11. 非目标

- 历史数据、协议、同步 runtime、旧 admin-ui 的迁移、兼容、fallback 或双写。
- 多币种、税务计算、发票、优惠码、试用、自动续费、按天折算、信用额度、部分退款。
- 平台管理员读取个人同步明文/密钥/个人凭据或组织资源正文。
- 组织资源字段 ACL、组织内容加密、账号删除、流量分析报表、MFA；必须另立规格，不得半实现混入本交付。
