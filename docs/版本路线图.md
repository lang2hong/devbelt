# DevBelt 版本路线图

> 状态：草案（2026-10-22）
>
> 本文定义 0.1.0 之后的版本策略、功能批次和发布顺序。
>
> `1.0.0` 不预先作为开发目标；它只在正式发布时创建。0.x 之间可以随时插入新功能版本。
>
> 0.2.0 有 [P10-Insight](工作包/P10-Insight.md) 可实施规格；0.3.0 已立项为 Agent，详见 [P12-Agent](工作包/P12-Agent.md)；0.4.0 立项为数据监控，详见 [P13-数据监控](工作包/P13-数据监控.md)；0.5.0+ 按需立项。

## 1. 版本策略

- 采用 SemVer：
  - **patch**（`0.2.1`）：只放修复、兼容性调整和发布门禁修复；
  - **minor**（`0.2.0` / `0.3.0` / `0.4.0` / 后续 `0.x.0`）：功能版本，允许行为变化；
  - **major**（`1.0.0`）：正式公开发布版，只在决定发布时创建，不提前绑定功能范围。
- `0.1.x` 不再承载新功能；0.1.0 发布后的修复走 `0.1.1`、`0.1.2`。
- 0.x 功能版本按需插入，不要求连续；可以随时新增 `0.5.0`、`0.6.0` 等。
- 功能版本必须有独立 CHANGELOG、验收矩阵和回滚方案。
- 高风险能力（AI 写操作、MCP、Migration、脱敏）必须默认关闭或默认只读，通过显式开关启用。

## 3. 0.x 功能批次

### 0.2.0 Insight

目标：把“查询 → 诊断 → 优化”做深。

- 可视化 EXPLAIN（MySQL / PostgreSQL / SQLite）
- 慢查询分析（本地历史；可选 `performance_schema` / `pg_stat_statements`）
- 索引建议（只建议，不自动执行）
- SQL 诊断（VS Code Diagnostics）
- 数据字典导出

详见 [P10-Insight](工作包/P10-Insight.md)。

### 0.3.0 Agent

目标：让 AI 从“问答”升级为受控执行，并把数据库能力安全地开放给外部 AI 客户端。

- AI Database Agent：查 Schema → 生成 SQL → 事务 dry-run → 展示影响 → 批准 → 执行/回滚
- MCP Server：只读 Schema / 查询 / EXPLAIN 工具，本地鉴权 + 审计
- 数据脱敏/子集化：PII 识别、确定性脱敏、FK 完整性、导出
- 共用 Tool Registry、风险分级、审批策略、独立会话与审计

> 工作包文档：[P12-Agent](工作包/P12-Agent.md)（草案待审，审阅通过前不作为可实施规格）。

> 明确不做：后台自主运行、自动批准写操作、生产默认写、云端 MCP、团队 ACL。MySQL DDL 隐式提交，不承诺事务回滚。

### 后续候选能力（不绑定版本）

以下能力不预先绑定 `1.0.0` 或某个具体 0.x 版本；由用户反馈和战略决定何时插入：

- dbt 集成：manifest/catalog、model 预览、lineage、run/test
- SQL Server：连接、元数据、查询、DDL、导入导出、事务、类型映射
- 发布硬化：真实引擎矩阵、干净 Profile VSIX、性能基准、安全评审、Marketplace 素材

> `1.0.0` 只在决定正式发布时创建，届时再确定该版本包含哪些候选能力。

## 4. 依赖关系

```text
0.2.0 Insight
  ├─ EXPLAIN 解析器 / 统一计划模型
  ├─ 查询历史聚合
  ├─ 索引建议规则
  ├─ SQL Diagnostics
  └─ 数据字典生成

0.3.0 Agent
  ├─ Tool Registry + Approval Policy
  ├─ TransactionService（dry-run / 影响预览）
  ├─ MCP Server（只读 + 本地 IPC/HTTP）
  └─ Masking Engine

0.4.0+ / 1.0.0
  ├─ dbt Adapter（候选）
  ├─ SQL Server Dialect（候选）
  └─ 发布门禁（正式发布时）
```

## 5. 明确不做（当前范围外）

- Docker 本地数据库
- 云数据库 IAM 认证
- 团队版 / 团队共享连接 / 资源 ACL
- 通用第三方插件市场
- 完整 BI / 报表平台
- 多人实时协作编辑

## 6. 发布门禁

每个功能版本发布前必须通过：

- `typecheck` / `build` / 全量测试
- 对应引擎的真实库矩阵
- 干净 Profile VSIX smoke test
- 中英文词条完整、无死键
- 安全评审：凭据、日志、审计、只读/生产保护
- CHANGELOG、README、Marketplace 截图
- 回滚方案与备份路径

## 7. 变更控制

- 新功能默认走 feature flag 或配置开关。
- 破坏性行为变更必须写入 CHANGELOG 的 “Changed / 变更”。
- AI、MCP、Migration、脱敏相关能力的默认值必须是安全侧。
- 每个版本结束后更新本文的版本状态和 `docs/产品介绍.md`。

## 8. 维护

- 本文是版本线事实基线；已立项版本以对应 `P*.md` 为准，规划级版本以本文范围为准。
- 规划级版本不得当作可实施规格；立项后再补工作包文档、任务拆分与验收矩阵。
- `1.0.0` 不进入日常规划；正式发布时再确定范围、创建 tag 与发布说明。
- 版本发布后，将对应章节标记为“已发布”，并记录发布日期与版本号。
