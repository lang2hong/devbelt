# P13 · 数据监控（0.4.0）

> 状态：第一批实施中（2026-10-25，分支 `dev/p13-monitor`）；第二批未开始
>
> 目标版本：`0.4.0`
>
> 上游：`docs/版本路线图.md`；复用 [P12-Agent](P12-Agent.md) 的只读执行底座。
>
> 说明：本文是产品与工程范围草案；评审通过并确认验收矩阵后才进入编码。

## 1. 背景

用户希望在 AI Chat 里说一句「帮我监控这张表的数据变化」，之后由扩展定时检查，并在变化时提醒。

当前事实（已核实）：

- 没有任何定时查询或监控任务；唯一的定时能力是 `src/schedule/backupScheduler.ts`（进程内 `setInterval`，用于定时备份）；
- 只读执行底座已存在：`checkReadOnlySql`（`packages/agent-core`）只放行单条 `SELECT / WITH / VALUES`；`openIsolatedSql` 可以开独立会话，MySQL / PG 可设为会话级只读（Explain「实际执行」已采用这种方式）；
- 结果渲染组件已存在：AI Chat 的 `ToolResultInline` 支持表格和折线 / 柱状 / 饼图（`webview/src/components/ai/charts/`）；
- 连接树显示的表行数（如 `2589 rows`）来自 `table_rows`，即引擎估算值，不是精确值；
- 数据库客户端拿不到变更事件（binlog / logical replication 需要额外权限与部署），本工作包**只做定时只读查询 + 对比**。

## 2. 目标

1. 在不调用模型的前提下，为任意表提供**行数变化**监控（右键模板）；
2. 让 AI 根据用户描述提出**聚合指标**或**新增行**监控，由用户确认后创建；
3. 定时在独立只读会话上执行，按阈值弹出 VS Code 通知；
4. 在 AI Chat 中用卡片、折线图和表格展示任务状态与历史；
5. 默认安全：只读、生产连接默认拒绝、有频率与数量上限、VS Code 关闭即停止。

## 3. 非目标

- 真正的变更数据捕获（CDC）、触发器、binlog / WAL 订阅；
- 检测行的**修改与删除**明细（行数监控只能看到净变化）；
- VS Code 关闭后的后台运行、系统服务、服务端代跑；
- 全表快照对比（成本高，生产库不适合）；
- Redis / Elasticsearch 监控（首版只做 MySQL / PostgreSQL / SQLite）；
- 跨设备同步任务定义或历史数据；
- 由 AI 自主创建、修改或启动任务（AI 只能提出）。

## 4. 监控类型

| 类型 | 含义 | 查询 | 来源 |
|---|---|---|---|
| **A1 行数** | 表的总行数变化 | 扩展生成 `SELECT COUNT(*) FROM <表>` | 右键模板 / AI |
| **A2 聚合指标** | 一行多个数值，如 `lag_seconds`、`rows_last_1h`、`SUM(amount)` | AI 提出的单条 `SELECT`，返回 1 行、1–10 列数值 | 仅 AI |
| **B 新增行** | 某个单调递增列上「上次之后」的新行 | 扩展按表名与游标列生成，游标值用参数绑定 | 仅 AI |

右键入口**只提供 A1**：右键菜单无法知道用户想看哪一列；表里也不一定有 `create_time` 之类的列，即使有，也可能没有索引、允许为空或被改写。需要 A2 / B 的场景走「让 AI 帮我设置」。

## 5. 用户流程

### 5.1 右键：监控行数变化

```text
右键 oms_order → 监控行数变化…
  ┌ 监控 oms_order 的行数 ─────────────────────────┐
  │ 间隔      [ 5 分钟 ▾ ]                          │
  │ 提醒条件  [ 行数变化时 ▾ ]  （任意变化 / 增加超过 N / 减少超过 N）│
  │ ⚠ 估算约 120 万行，COUNT(*) 会扫描整表，已建议 30 分钟  │  ← 仅大表
  │                       [取消]  [创建并开始]      │
  └────────────────────────────────────────────────┘
```

- 不调用模型，不消耗积分；
- 创建时立即执行一次作为基线，结果显示在任务卡片里。

### 5.2 右键：让 AI 帮我设置监控

打开 AI Chat，选中该连接与库，打开 Agent 模式，并在输入框预填「帮我监控 `<表>`：」，由用户补充想监控什么。

### 5.3 在对话里描述

```text
你：帮我监控 oms_order，每 5 分钟看看有没有新订单，超过 20 单提醒我
AI：可以按 create_time 检查新增行：
    ┌ 监控提案 ───────────────────────────────────┐
    │ 类型      新增行                              │
    │ 表        oms_order                          │
    │ 游标列    create_time（datetime，有索引）       │
    │ 间隔      5 分钟                              │
    │ 提醒      新增 ≥ 20 行                         │
    │ 查询      SELECT * FROM `oms_order`           │
    │           WHERE `create_time` >= ? ORDER BY … LIMIT 51 │
    │                        [取消]  [创建并开始]    │
    └─────────────────────────────────────────────┘
```

- 提案来自 Agent 的新工具 `propose_monitor`；模型只能提出，**创建必须由用户点击确认**；
- 扩展在显示提案前完成第 6 节的校验；校验不通过时，提案卡片显示原因，不提供「创建」按钮；
- 表里没有合适的游标列时，工具返回明确错误，模型应建议改用行数监控，而不是编造列名。

### 5.4 运行中

- 对话里的任务卡片和「⋯ → 后台任务」抽屉显示：名称、类型、间隔、上次运行时间与结果、状态（运行中 / 已暂停 / 出错）、操作（暂停 / 继续 / 立即运行 / 删除 / 让 AI 解读）；
- 详情：A 类显示最近数据点的折线图 + 表格（时间、值、变化量）；B 类显示最近一次新增行的表格（最多 50 行）+ 每次新增数量的柱状图；
- 状态栏在有运行中任务时显示 `$(pulse) N`，点击打开「后台任务」抽屉。

## 6. 校验规则

### 6.1 通用

- 连接必须是 MySQL / PostgreSQL / SQLite；
- 生产连接（`environment === 'production'`）默认拒绝，需开启 `devbelt.ai.monitor.allowProduction`；
- 表名、schema、列名都经 `validateIdent` / `validateSchemaIdent` 校验，并由方言负责加引号；
- 数量上限：每个连接最多 5 个任务，全部最多 20 个；
- 间隔：最短 1 分钟，最长 24 小时，默认 5 分钟。

### 6.2 A2 聚合指标

- SQL 必须通过 `checkReadOnlySql`，并且 `kind === 'select'`（不接受 `EXPLAIN`）；
- 创建前在只读会话上**试执行一次**：结果必须恰好 1 行、1–10 列，并且每列都可解析为有限数值（`NULL` 视为缺值，不报错）；否则拒绝并给出原因；
- 每列各画一条线；提醒条件绑定**其中一列**（例如新鲜度监控的 `lag_seconds` 高于 600），其他列只记录、不提醒；
- 试执行沿用查询超时；超时即拒绝创建（定时执行同样会超时）。

### 6.3 B 新增行（游标列）

| 检查 | 不满足时 |
|---|---|
| 列存在于该表 | 拒绝 |
| 类型为整数（`int` / `bigint` / `serial` 等）或时间（`datetime` / `timestamp` / `timestamptz` / `date`） | 拒绝 |
| SQLite 只接受 `INTEGER` 列（含 `rowid` / 整数主键）；`TEXT` 存时间的列首版不支持 | 拒绝 |
| 列允许为空 | 提示：空值行永远不会被检测到 |
| 列上没有可用索引（作为索引首列） | 提示：每次检查都会扫描整表 |
| 表没有主键 | 提示：同一游标值上的行可能重复或遗漏 |

列信息读取复用 `MetadataService.getColumns` / 索引元数据，不调用模型。

### 6.4 大表

- 参考连接树已有的估算行数（MySQL `TABLE_ROWS`、PG `reltuples`；SQLite 无估算）；
- 估算超过 100 万行时，A1 的确认框给出成本提示，并把默认间隔改为 30 分钟（用户仍可改短，不低于 1 分钟）；
- 不用估算值代替 `COUNT(*)`：InnoDB 的 `TABLE_ROWS` 误差可能很大，拿它比较「变化」会误报。

## 7. 执行设计

### 7.1 调度

- 进程内调度器（参考 `backupScheduler`）：每个任务一个计时器，首个间隔加 0–10% 随机抖动，避免多个任务同时触发；
- **不重叠**：上一次还没结束时跳过本次，并记一次「跳过」；
- 同一连接的任务串行执行，共用一个独立只读会话；会话空闲 10 分钟后关闭，下次运行时重开；
- 连接被删除或被修改（主机、库变化）时，相关任务自动暂停，并标记「连接已变更」。

### 7.2 会话

- `openIsolatedSql` 开独立会话，与查询面板、树视图、Agent 互不干扰；
- MySQL `SET SESSION TRANSACTION READ ONLY`、PG `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`；SQLite 连接本身需为只读连接，否则先用 `PRAGMA query_only = ON`；
- 查询超时取 `devbelt.ai.monitor.queryTimeoutSeconds`（默认 30 秒），不沿用 300 秒的全局默认值；
- 每次执行都带 `skipHistory: true`，不写入查询历史，以免冲掉用户自己的历史记录。

### 7.3 B 类游标与去重

```text
SELECT * FROM <表> WHERE <游标列> >= ? ORDER BY <游标列>, <主键…> LIMIT 51
```

- 游标初值：创建时的 `MAX(<游标列>)`（只看「之后」，不回放历史数据）；
- 使用 `>=` 而不是 `>`，同一游标值上已见过的行按主键去重（只保留最大游标值那一批的主键集合）；
- 返回 51 行时表示「至少 50 行，还有更多」，游标推进到本批最大值，下次继续；
- 游标值只用参数绑定，不拼接进 SQL。

### 7.4 阈值与通知

| 类型 | 可选条件 | 默认 |
|---|---|---|
| A1 / A2 | 任意变化 / 增加 ≥ N / 减少 ≥ N / 变化 ≥ N% / 高于 X / 低于 X | 任意变化 |
| B | 新增 ≥ N 行 | N = 1 |

- 命中时弹 VS Code 通知（`showInformationMessage`，阈值类用 `showWarningMessage`），按钮为「查看」「暂停此任务」；
- 同一任务 15 分钟内最多通知一次（`devbelt.ai.monitor.notifyCooldownMinutes`），冷却期内的命中只更新卡片；
- 连续失败 3 次：单独发一条警告通知，并**自动暂停**该任务，卡片显示最后一次错误。

### 7.5 生命周期

- 任务定义保存在本地；VS Code 关闭即全部停止；
- 下次启动时所有任务为**已暂停**，需要用户逐个或一键「继续」；不在用户不在场时自动恢复对数据库的查询；
- 暂停 / 继续 / 删除 / 修改间隔都只能由用户在 UI 中操作。

### 7.6 存储

| 内容 | 位置 | 说明 |
|---|---|---|
| 任务定义 | `<globalStorage>/monitor/tasks.json` | 连接 id、库、schema、表、类型、SQL 或游标列、间隔、阈值、状态；不含凭据 |
| 历史数据点 | `<globalStorage>/monitor/<taskId>.jsonl` | 每次一行：时间、值或新增行数、耗时、错误码；每个任务最多保留 500 行 |
| B 类新增行 | 仅内存 | 只保留最近一次（≤ 50 行），不落盘，减少本地明文留存 |

- 不进入个人同步，不上传服务端；
- 删除任务时一并删除其历史文件。

## 8. AI 集成

- 新增 Agent 工具 `propose_monitor`（风险级别 R1：只读提议，不执行）：参数为类型、表、可选 schema、A2 的 SQL 或 B 的游标列、间隔、阈值；
- 工具处理器执行第 6 节的校验，返回提案或拒绝原因；只有用户点击卡片上的「创建并开始」才真正创建任务；
- 普通对话（未开 Agent）中提到监控时，提示用户打开 Agent，或使用右键「监控行数变化」；
- **定时执行不调用模型**；只有创建时，以及用户点击「让 AI 解读」时才调用模型；
- 「让 AI 解读」默认只发送指标历史（时间与数值）；B 类的新增行内容不发送给模型，除非用户在确认中勾选「附带最近新增行」（沿用 `includeSample` 的确认思路）。

## 9. 安全与隐私

- 只读：SQL 门禁 + 数据库会话只读，两层防护；
- 生产默认拒绝；
- 标识符校验 + 参数绑定，模型无法通过列名或游标值注入 SQL；
- 频率与数量上限、单次超时、不重叠执行，避免监控本身成为数据库负载；
- 本地审计（`AuditLogger`）：创建、删除、暂停、继续、自动暂停、通知触发；记录任务 id 与表名，不记录行内容；
- 新增行明细不落盘，默认不发送给模型。

## 10. 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `devbelt.ai.monitor.enabled` | `true` | 关闭后隐藏入口并停止所有任务 |
| `devbelt.ai.monitor.allowProduction` | `false` | 允许在生产连接上创建监控 |
| `devbelt.ai.monitor.queryTimeoutSeconds` | `30` | 单次检查超时 |
| `devbelt.ai.monitor.notifyCooldownMinutes` | `15` | 同一任务两次通知的最短间隔 |
| `devbelt.ai.monitor.maxTasks` | `20` | 全部任务上限（每个连接固定 5 个） |

## 11. 已知限制（会写进用户文档）

- 行数监控只看到净变化：同时新增 10 行、删除 10 行显示为「无变化」；
- 新增行监控检测不到修改和删除；
- 游标列有空值、时钟回拨或被改写时可能漏行；没有主键的表可能重复或遗漏；
- `COUNT(*)` 在大表上有成本；
- VS Code 关闭期间不监控，重新打开后任务为暂停状态。

## 12. 测试矩阵

### 单元测试

- A1 SQL 生成（三种方言，含 PG schema、带特殊字符的表名被拒绝）；
- A2：`checkReadOnlySql` 拒绝写语句、多语句、`EXPLAIN`；试执行结果形状校验（0 行、多列、非数值）；
- B：列存在性、类型白名单（三种方言）、可空 / 无索引 / 无主键提示；游标 `>=` + 主键去重；51 行截断与游标推进；
- 阈值：各条件的命中与不命中；冷却期；连续 3 次失败后自动暂停；
- 调度：不重叠、抖动范围、同连接串行、启动后全部暂停、上限（每连接 5 / 全部 20）、生产拒绝；
- 存储：历史 500 行裁剪、删除任务时删除历史文件、B 类行不落盘；
- `propose_monitor`：校验失败时返回原因，不创建任务；确认前不执行任何定时查询。

### 真实库（`db_client_verify` / 本地 SQLite）

- MySQL：A1 / A2 / B 端到端，期间插入数据，验证检测与通知；会话只读时写操作被拒；
- SQLite：A1 与整数游标的 B；
- PG：本地无环境，CI 中执行。

### 手工 UI

- 右键创建、大表提示、AI 提案卡片、抽屉、折线图与表格、通知按钮、状态栏计数、重启后暂停。

## 14. 风险与开放问题

已确认（2026-10-25）：

| 问题 | 结论 |
|---|---|
| 提案确认用对话内卡片还是原生模态框 | 对话内卡片（只读操作，和写审批的原生模态区分） |
| 「让 AI 帮我设置」是否自动打开 Agent | 是；否则模型无法调用 `propose_monitor` |
| 多窗口同时打开时任务会重复执行 | `globalStorage` 锁文件 + 15 秒心跳（45 秒过期接手）：只有持锁窗口执行，其他窗口只显示 |
| A2 是否只允许 1 行 1 列 | 改为 1 行多列（≤ 10 列），提醒绑定其中一列；来自 `lc_data_event` 新鲜度监控的实际需求 |

仍开放：

| 问题 | 当前倾向 |
|---|---|
| 通知是否需要声音 / 系统级通知 | 否，只用 VS Code 通知 |
| 是否支持 Redis / ES | 首版不支持，按反馈再定 |
| 是否允许 TEXT 时间列作为 SQLite 游标 | 首版不支持；字符串比较依赖格式一致，风险高 |
