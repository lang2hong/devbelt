# P4 — 支付闭环

> 状态：核心下单/回调/权益已交付；待生产门禁（账单对账、重复付款闭环、证书轮换、沙箱/真实验收、金标向量）。
>
> 上游：`docs/发布与运维.md` §5/§6。

## 目标

接入微信支付和支付宝，完成订阅下单、回调、订单状态机、权益生效和对账。

## 范围

### 支付能力

- 套餐定义：Free（免费，0 元）、Pro（个人付费）。
- 套餐权益（entitlementSnapshot JSON 存于 `personal_subscriptions`）：
  - Free：MySQL + SQLite，个人连接同步 500 条/32MiB，最多 3 台设备。
  - Pro：MySQL + PostgreSQL + SQLite，同步记录/字节/设备数按套餐配置。
- 支付渠道：微信 Native 支付（扫码）、支付宝网页支付（H5 跳转）。
- 订单状态机：`pending` → `paid` → `fulfilled` / `failed` / `refunded` / `expired`。
- 回调签名验证：微信/支付宝回调签名严格校验，幂等处理。
- 支付成功后更新 subscription.entitlementSnapshot 和到期时间。
- 订单历史查询、发票申请。
- 对账：每日拉取微信/支付宝对账单与本地订单比对，差异报警。

### 不在 P4 范围

- 退款自动化（P4 只支持退款状态记录，退款走人工流程）。
- 多币种（仅 CNY）。
- 优惠券、促销码。
- 订阅自动续费（v1 为单次购买时长包，续费通过到期提醒 + 用户主动续购）。
- 海外支付（Stripe/PayPal）。

## 服务端设计

### 数据模型

- `orders` 表：`order_id`、`user_id`、`plan_code`、`amount_cents`（BIGINT UNSIGNED，CNY 分）、`channel`（wechat/alipay）、`status`、`channel_trade_no`、`paid_time`、`expires_time`、`created_time`、`updated_time`。
- `payments` 表：支付流水（回调原始数据、签名验证结果、处理时间），与 orders 一对多（支持重试/多次回调）。
- `invoices` 表：发票申请记录（抬头、税号、邮箱、状态）。
- 金额一律 CNY 分 `BIGINT UNSIGNED`，服务端不接受前端传入金额（金额由后端按 plan_code 计算）。

### 状态机规则

- 下单时创建 order 状态 `pending`，过期时间（建议 30 分钟）。
- 回调到达时：
  1. 验证签名；
  2. 按 channel_trade_no 幂等（重复回调不重复处理）；
  3. 若订单已 expired/refunded → 记录流水但不改状态；
  4. 支付成功 → 置 `paid`，在同一事务内更新 subscription（权益/到期时间）→ 置 `fulfilled`。
- 支付商事件只推进订单状态，不直接绕过订单写 subscription。
- 对账差异：记录 `reconciliation_issues` 表，人工介入。

### 金额与安全

- 所有金额计算在服务端；前端只展示 plan_code 和价格，不参与金额计算。
- 回调接口不依赖 session/cookie，走渠道签名校验；防重放由「签名完整性 + 时间戳 freshness + 交易号唯一约束 + 状态机幂等」构成（nonce 不持久化去重，记为后续强化）。
- 所有支付相关写操作加事务和行锁（`FOR UPDATE` 锁订单行）。
- 不记录银行卡号、支付密码等敏感信息；只存平台返回的 trade_no 和必要交易信息。

## 前端入口

- VS Code 扩展内：账户面板展示订阅状态、套餐选择、支付二维码/跳转链接（Webview 展示，或调起系统浏览器打开 `/console/checkout`）。
- 控制台 `/console/checkout/:orderId` 展示支付二维码或跳支付宝，轮询订单状态。
- 支付成功回跳 `/console/checkout/success`。

## 前置依赖

- P3 控制台 UI（支付页面托管）。
- 用户表/订阅表结构确认（当前已有 `personal_plans`/`personal_subscriptions` 基础表，P4 扩展）。
- 微信/支付宝商户号和证书配置（环境变量，不入仓库）。

## 验收

- 微信扫码支付：创建订单 → 扫码 → 回调 → 权益生效 → 订单状态 fulfilled。
- 支付宝网页支付：创建订单 → 跳转支付宝 → 支付成功跳转回 → 权益生效。
- 重复回调、过期订单支付、签名伪造回调均安全拒绝。
- 金额单位始终为 CNY 分，无浮点精度错误。
- 对账脚本跑通当日对账单，无未解释差异。
- 支付过程不泄露商户密钥、证书、用户支付凭据。
- 支付后 Pro 权益（含 PostgreSQL 连接、更多同步配额）在 VS Code 扩展下次刷新 entitlement 后生效。

## 测试要求

- 支付单元测试：签名验证、状态机转移、幂等回调、金额计算、并发回调（行锁验证）。
- 使用微信/支付宝沙箱环境联调。
- CI/沙箱不跑真实资金测试；生产启用前由授权人员完成受控人工真实资金验收；生产商户号配置走环境变量注入。
