# 个人同步路线图

本文件只记录同步领域现状；正式实现路径、插件接线和验收以[完整交付实施规格](完整交付实施规格.md)第 4 节、第 9 节和第 10 节为准。

## 目标

在同一账号的设备间端到端加密同步个人连接配置。服务端只保存密文和协议元数据，不能读取连接凭据或客户端密钥。

## 已实现

- 服务端状态、record、变更流、签名、nonce 防复用、幂等回执和配额。
- 初始化、换钥、恢复、销毁和丢失后重置协议。
- 扩展端 DEK、HKDF、Ed25519、AES-GCM、Argon2id 和恢复码组件。
- 扩展端协议客户端、状态快照、record codec、record map 和 outbox。
- 持久化健全性：`RecordMapStore.put()` 冲突失败不破坏原映射（copy-on-write）；`RecordMapStore` 与 `PendingMutationStore` 读改写串行化；`StateStore.setSnapshot()` 返回并传播持久化 Promise。
- 预留映射顺序（任务 1）：新 record 先预留 recordId→connectionId 映射（pending），再写连接并确认版本（`applyRecords`）。
- 同步循环（任务 2）：`SyncEngine` 单飞运行——epoch/stateVersion 对账、outbox 已签名直发重放（逐字复用 signature/requestDigest，不重签）、分页 pull/apply/逐页 cursor。

这些组件尚未接入完整用户流程。

## 当前任务

3. 接入连接变更监听，并确保远端应用不会再次触发上传。
4. 实现初始化、解锁、换钥、恢复、销毁和丢失后重置界面。
5. 将 Argon2id 放入 Worker，避免阻塞扩展宿主。
6. 完成网络中断、重启恢复、冲突、epoch 变化和双设备测试（引擎级/单测已覆盖；双设备 E2E 未做）。

## 验收

- 两台真实设备可以创建、更新和删除连接，并在中断与重启后收敛。
- 服务端无法读取连接明文、DEK、同步口令、恢复码或私钥。
- outbox、record map 和 cursor 在并发及持久化失败时不丢数据。
- 本地脏连接遇到更高远端版本时保留本地数据并报告冲突。
- 销毁和重置后不会继续使用旧 epoch 的状态或密钥。
- Node 20/22、单元测试、真实 MySQL 集成测试、构建和扩展打包全部通过。
