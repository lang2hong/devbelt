# 个人同步路线图

本文件只记录同步领域现状；正式实现路径、插件接线和验收以[V3 完整交付实施规格](V3完整交付实施规格.md)第 4 节、第 9 节和第 10 节为准。

## 目标

在同一账号的设备间端到端加密同步个人连接配置。服务端只保存密文和协议元数据，不能读取连接凭据或客户端密钥。

## 已实现

- 服务端状态、record、变更流、签名、nonce 防复用、幂等回执和配额。
- 初始化、换钥、恢复、销毁和丢失后重置协议。
- 扩展端 DEK、HKDF、Ed25519、AES-GCM、Argon2id 和恢复码组件。
- 扩展端协议客户端、状态快照、record codec、record map 和 outbox。

这些组件尚未接入完整用户流程。

## 当前任务

1. 修复 `RecordMapStore.put()` 冲突失败时破坏原映射的问题。
2. 串行化 `RecordMapStore` 与 `PendingMutationStore` 的读改写。
3. 让 `StateStore.setSnapshot()` 返回并传播持久化 Promise。
4. 新 record 先稳定预留 recordId 到 connectionId 的映射，再写连接并确认版本。
5. 实现状态对账、outbox 重放、push、pull、远端应用和 cursor 提交的同步循环。
6. 接入连接变更监听，并确保远端应用不会再次触发上传。
7. 实现初始化、解锁、换钥、恢复、销毁和丢失后重置界面。
8. 将 Argon2id 放入 Worker，避免阻塞扩展宿主。
9. 完成网络中断、重启恢复、冲突、epoch 变化和双设备测试。

## 验收

- 两台真实设备可以创建、更新和删除连接，并在中断与重启后收敛。
- 服务端无法读取连接明文、DEK、同步口令、恢复码或私钥。
- outbox、record map 和 cursor 在并发及持久化失败时不丢数据。
- 本地脏连接遇到更高远端版本时保留本地数据并报告冲突。
- 销毁和重置后不会继续使用旧 epoch 的状态或密钥。
- Node 20/22、单元测试、真实 MySQL 集成测试、构建和扩展打包全部通过。
