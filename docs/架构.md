# 架构

## 总体结构

```
┌─────────────────────────────────────────────────────────┐
│                    VS Code Extension                     │
│  ┌──────────┐  ┌──────────┐  ┌───────────────────────┐  │
│  │ db-core   │  │ vscode-  │  │  sync (底层/运行时   │  │
│  │ (driver,  │  │ ext UI,  │  │  /UI 已实现，命令    │  │
│  │  query,   │  │ commands,│  │  已注册，待双机验证)  │  │
│  │  dialect) │  │ trees,   │  │                        │  │
│  │           │  │ webview) │  │                        │  │
│  └──────────┘  └──────────┘  └───────────────────────┘  │
└─────────────────────────┬───────────────────────────────┘
                          │ HTTPS /api
┌─────────────────────────┴───────────────────────────────┐
│                      Fastify Server                      │
│  auth | me | personal | sync                             │
└─────────────────────────┬───────────────────────────────┘
                          │
                     MySQL 8
```

五个包：

| 包 | 路径 | 职责 | 依赖 |
|---|---|---|---|
| db-core | `packages/db-core` | 数据库驱动适配、SQL 方言、连接池、查询执行、元数据、数据操作 | 无 VS Code/服务端依赖 |
| ai-core | `packages/ai-core` | Provider 无关的 AI 传输核心：OpenAI 兼容 Provider、SSE parser、schema 序列化、SQL 安全分类复用、敏感列打码、prompt 契约（含 NL2SQL v5）、`parseSqlAnswer` | db-core（复用 SQL 词法/风险分类） |
| db-host | `packages/db-host` | 宿主无关的编辑器侧逻辑：连接/查询数据层、同步客户端、会话装配、E2EE 同步引擎与密钥生命周期 | db-core |
| vscode-ext | `apps/vscode-ext` | VS Code 生命周期、命令、树视图、Webview（同步装配已下沉 db-host） | db-core、db-host |
| server | `apps/server` | 身份认证、权益、设备、个人同步协议、MySQL 持久化 | 无 VS Code 依赖 |
| db-hostd | `apps/db-hostd` | 把 db-host 暴露为 stdio JSON-RPC 的 sidecar，供非 VS Code 宿主（如未来的 IntelliJ 插件）复用 | db-host、db-core |

## db-hostd

- **协议**：stdin/stdout 逐行 NDJSON JSON-RPC（一请求一响应），入口 `apps/db-hostd/src/index.ts`。
- **方法**：`ping`、`dek.generate|store|load|delete`、`entitlement.allowedEngines`、`sign.requestDigest|stateInput|recordInput|signInput`、`sync.getMe`。
- **端口实现**：`FileSecureStorage`（`SecureStorageLike`，0600 明文文件）与 `FileMemento`；生产桌面宿主应注入各自安全存储。
- **配置**：`DEVBELT_DB_HOSTD_HOME`（默认 `./.devbelt-db-hostd`）。

## db-host

- **端口（ports）**：`packages/db-host/src/hostTypes.ts` 定义 `SecureStorageLike`（等价 `vscode.SecretStorage` 最小面）等宿主能力接口；各宿主注入实现，db-host 本身零 `vscode` 依赖。
- **连接/查询数据层**：`ConnectionStore`、`QueryStore`（memento + SecretStorage，经端口注入）。
- **同步**：`SyncClient`（HTTP/双 token/重试）、`session`/`sessionFactory`/`runtimeFactory`（会话装配）、`crypto/*`（JCS/HKDF/Ed25519/Argon2 worker）、`e2e/*`（同步引擎、状态/映射/outbox/冲突）。
- **测试**：`apps/vscode-ext/test/` 通过 vitest alias 直接跑 db-host 源码；移动端相关用例的 undici mock 由 `syncFetch` seam 承接。

## db-core

- **Dialect**：MySQL、PostgreSQL、SQLite 三种方言，各自实现 SQL 生成、元数据查询、类型转换。
- **Connection**：统一连接接口，各引擎驱动适配，连接池管理。
- **Query**：SQL 执行、结果集解析、元数据服务（数据库/表/列/索引/视图/例程/事件/触发器/外键）。
- **TableService**：DDL 生成、表结构操作。
- **Export/Import**：CSV、JSON、XML、XLSX、SQL dump 的导入导出。
- **Redis**（P7）：`src/redis/` 纯 Node ioredis 封装（`RedisClient`：只读切面 + 写命令 denylist、命令白名单、SCAN、五类型 CRUD、`runExclusive` 串行、`natMap` 函数化），零 vscode 依赖。
- **Elasticsearch**（P8）：`src/elasticsearch/` 纯 Node `http`/`https` 实现的 `EsClient`（统一 request 封装 + JSON body/超时/AbortSignal、只读切面 fail-closed、危险判定、请求日志），零 vscode 依赖、零新依赖。
- **SQL 风险分类（P9）**：`src/sql/risk.ts` 为全仓唯一 `analyzeSqlRisk`/`classifyWriteKind` 实现；
  vscode-ext `utils/sqlRisk.ts` 为 re-export shim —— 执行门禁与 AI 标签共用，防两套分类器漂移。
- **Validation**：标识符校验、SQL 安全确认。
- **有意例外**：`src/sync/`（JCS/签名测试向量）与 `testing` 子路径不属于数据库核心职责，但向量需在 vscode-ext 与 server 两侧共用，故寄居 db-core 经 `./testing` 导出（只含公开向量，无私钥）。属记录在案的有意例外，非职责漂移。

## ai-core

- **传输**：`OpenAICompatibleProvider`（Node 全局 fetch + SSE 流式 + 超时/AbortSignal + auth/rate-limit/quota/network/timeout/abort/protocol 错误分类）、SSE parser（`./sse` 子路径导出，服务端代理复用）。
- **上下文**：`serializeSchema`（表/列/索引/外键 + ENUM 随列类型 + 列注释 120 字清洗 + 状态列字典片段 500 字上限；3-4K 预算）、`formatRowSample`（样本打码/截断/二进制占位）、sensitive 黑名单（精确词边界）。
- **Prompt 契约**：固定 system prompt（注入防御 + 语言跟随）+ 六场景 builder（nl2sql v5：schema-linking/ENUM 严格映射/意图复述/Assumptions/引用表/域上下文与业务规则区块）+ inline 续写契约（`<none>` 哨兵）。
- **解析**：`parseSqlAnswer`（复述/sql/假设，布局容错）；`classifyAiSql`（复用 db-core 风险分类）。
- **依赖边界**：零 `vscode`、零第三方运行时依赖；仅依赖 db-core 的 SQL 词法/风险导出。

## vscode-ext

### Activation 流程

`extension.ts` 的 `activate()` 按以下顺序初始化（注意：`AuthService` 在 ConnectionManager 之前创建，但其 token 恢复 `auth.init()` 在 ConnectionManager/DbTreeDataProvider 构造之后才 await）：

1. `ConnectionStore`：从 `globalState` 恢复连接和分组，明文凭据迁移到 `SecretStorage`。
2. `AuthService` 实例创建（尚未从 SecretStorage 恢复 token）。
3. `ConnectionManager`、`DbTreeDataProvider`、`QueryExecutor`、`ConnectionContext`、`HistoryStore`、`AuditLogger`、`BackupScheduler`。
4. Webview 初始化（BaseWebView、TableQueryView）。
5. `await auth.init()`：从 SecretStorage 恢复 access/refresh token；若已登录则 `void refreshEntitlement()` 异步拉取 `/api/db/me`。
6. `syncLoggedInContext(auth)` 设置 `devbelt.loggedIn` 上下文键。权益缓存（`devbelt.sync.cachedEntitlement`）由 `AuthService.getMe()` 统一落盘——init、AccountHubView 打开时都会刷新；本地连接**不走权益门禁**（本地引擎支持只看方言是否注册），权益缓存仅用于个人同步入站 record 过滤（PG 连接同步为 Pro 权益）。
7. `AuthenticatorStore`（P5 验证器）：`await authStore.init()` 预热 `secretCache`（逐条读 SecretStorage；单条失败标 `missingSecrets`，不中断激活）；订阅 `AuthenticatorChangedEvent → AuthenticatorView.refreshCurrent()`；store 经 `Deps.authStore` 交给 `registerCommands`。验证器面板按需打开、不预建、不占活动栏。
8. 事件订阅：连接变更/DDL 刷新树、配置变更切换语言、文档保存更新保存查询。
9. 创建个人连接树视图 `devbelt.explorer`。
10. SQL 补全和 CodeLens 注册。
11. 注册直连命令（openTerminal、designTable、newTableDesigner、serverStatus、ER 图、数据对比、仪表盘、审计日志、连接池、定时备份）。
12. `registerCommands()` 注册所有子模块命令（connection、query、table、database、user、account、group、ddl、search、explorerMenu、authenticator）。
13. PersonalSyncSession **不在 activate() 中创建**；首次用户调用 Initialize/Unlock 同步命令时懒创建，注册到 `context.subscriptions`。未解锁前不创建 SyncEngine/Coordinator、不发起任何 sync API 请求。

### 命令架构

- `commands/shared.ts` 提供 `makeSub(context)`，统一通过 `vscode.commands.registerCommand` 注册并自动加入 `context.subscriptions`。
- 命令按领域拆分到 `commands/` 目录下各文件：connection、query、table、database、user、account、group、ddl、search、authenticator。
- `test/commands/commandRegistration.test.ts` 自动校验 `package.json` 声明的每条命令都有注册调用点。

### 树视图

- **个人连接树**（`devbelt.explorer`）：`DbTreeDataProvider` 读取 `ConnectionStore.getVisibleTreeData()`，按分组层级展示连接和数据库元数据。节点 contextValue 编码数据库类型，菜单 when 直接匹配，消除时序竞态。

### Redis 客户端（P7）

- **引擎接缝**：`ConnectionSession` 是 `sql | redis` 判别联合（`src/connection/connectionSession.ts`）；`ConnectionManager.buildSession` 按 `dbType` 分派，Redis 走 `buildRedisSession`（standalone / cluster / sentinel，SSH 经 NAT map）。SQL 路径零行为改动。
- **树内键导航**：`DbTreeDataProvider` 对 Redis DB 节点懒 `SCAN` 一页 → `groupRedisKeyChildren` 客户端折叠；软上限 20000 / 硬上限 100000（`__full__` 快照 + 写操作定向失效）；cluster 逐 master。
- **安全边界**：只读连接 fail-closed；生产环境写操作二次确认；有损（非 UTF-8）键/成员只读 + 删除计数校验；string 支持字节级 hex。
- 连接颜色标签 `color` 为所有引擎共用字段。

### PostgreSQL 多 schema 与多库（P7.1）

- **schema 维度**：`capabilities.schemas`（PG true）；树为 `库 → Schema → 分类 → 对象`（`public` 置顶、系统 schema 不列）。`qualifyTable(dbType, table, database?, schema?)` 为 PG 单开 schema 通道，写/DDL/导出/数据编辑按 `"schema"."对象"` 限定；schema 由**显式** `node.schema` 提供（`pgSchemaFor`，绝不从 `database` 推断）。
- **多库（B2）**：`capabilities.multiDatabaseExplorer`（PG true，库列表按 `has_database_privilege CONNECT` 过滤）。`ConnectionManager.connect(conn, database?)` 对 PG 建**衍生库会话**（会话键含 database，同连接上限 4 + LRU）；SSH 隧道按 `connId` 引用计数复用；衍生会话不计入并发连接数门禁。PG 节点 `database`=库名、`schema`=命名空间；搜索遍历 库 × schema。
- **同连接跨 schema 对比/同步**：PG 连接绑定单库，故把「跨库」映射为**同一连接内跨 schema**——`compareSchema`/`compareData`/`syncDatabase` 在 schema 节点上选目标 schema；`SchemaDiffService`/`DataDiffService`/`DataTransferService` 透传 `sourceSchema/targetSchema`（对象按各自 schema 限定）。**可执行同步覆盖 表/列/PK/唯一/CHECK/外键/索引/新增序列**，serial 序列会创建（含 `OWNED BY`）并在数据导入后 `setval` 推进；**视图/函数/触发器仅输出为注释（不在同步中执行，需人工审阅依赖顺序）**；不处理 已存在序列的参数变更、函数签名变更、自定义类型。目录读取用隔离会话 + `SET search_path=pg_catalog` 强制完全限定名。schema 名放宽到含空格/`.`/引号（`validateSchemaIdent` + 引用层防注入）。PG 跨库对比仍不支持；不提供 `USE`。`syncDatabase` 由设置 `devbelt.pg.syncEnabled` 门禁（默认关，待真库验证）。

### Elasticsearch 客户端（P8）

- **引擎接缝**：`ConnectionSession` 扩第三种 `elasticsearch`；`ConnectionManager.buildSession` 按 `dbType` 分派（http/https、Basic/ApiKey、TLS、SSH 隧道、只读），SQL/Redis 路径零行为改动。
- **客户端**：db-core `EsClient` 零依赖封装；只读切面 fail-closed（GET/HEAD 恒放行；非 GET 仅 POST 且命中读路径白名单；`/_nodes` 管理端点与 `_bulk` 等一律 403，可单条解锁）；危险操作 host 侧确认（DELETE/`_cluster/settings`/`_all`、typed index 强确认）；写请求落审计。
- **面板**：单面板多 tab（cluster/indices/index/documents/dsl/rest/nodes/log）；Mapping/Settings/Aliases 只读展示；文档 `search_after` 分页 + CRUD；REST 控制台任意 method/path/body（query 透传、1MB 截断、在途请求独立 abort）。
- **树/凭据**：连接节点 → 集群 + 索引懒加载；password/ApiKey 入 `SecretStorage`、CA/cert 路径入 Memento、不落 webview。

### AI 能力（P9）

- **双通道**：`AiKeyStore`（apiKey 仅 SecretStorage，多窗口变更失效）+ `AiService` 双 provider 路由
  （server-proxy 复用 access token；openai-compatible 直连上游），每请求独立 AbortController。
- **面板**：独立 `devbelt.ai` WebviewPanel（`aiChat.html` 独立 vite 入口 + 独立 `aiProtocol`，不走
  WebviewMode）；会话/域上下文/默认指令存本地 Memento，不进 E2EE 同步。
- **场景接缝**：`nl2sqlRunner` 五路信号组装；`aiEditor`（Alt+A 直插 + 假设/复述状态条 + "在 Chat 中细化"、
  右键解释/优化）；错误诊断（`sqlForAi/secretRisk` + host 二次脱敏 `diagnosePayload`）；数据问答（样本
  默认不发、确认后打码）；0 行诊断（`aiSqlRegistry` 归因）；Chat 代码块"插入编辑器/执行"（复用
  QueryExecutor gate）；Inline 补全（`aiInlineProvider`，仅 Alt+/ 触发，light schema ≤1.5K）。
- **叶子视图桥**：`AiBridge`（模块级单例，未初始化时视图给提示不抛；AI 关闭不阻塞 SQL/Redis/ES 主流程）。
- **安全边界**：AI 永不自动执行；敏感列注释默认参与（连接级开关 + 发送计数）；口令字面量剥离/阻断。

### 验证器（P5 · 本地，无同步）

- **存储**：条目/分组/标签元数据入 `context.globalState`（`devbelt.authenticator.entries|groups|tags`）；TOTP secret 单独入 `SecretStorage`（键 `devbelt.authenticator.<id>.secret`，存规范化 base32）。运行期 `secretCache` 内存缓存供每秒算码，**只从缓存读**、不打 Keychain。
- **算法**：`base32.ts`/`totp.ts`/`otpauth.ts` 为纯函数（RFC 4648 §6 / RFC 4226 / RFC 6238），零第三方依赖、不 import vscode。
- **面板**：`AuthenticatorView`（viewType `devbelt.authenticator` 的 WebviewPanel，复用 `BaseWebView` 两次 ready 与 `retainContextWhenHidden`）；命令 `devbelt.authenticator` / `.add` / `.export`（后两者 `commandPalette` `when:false`，只走面板按钮）。**不新增活动栏图标/视图贡献**。
- **安全边界**：secret 不进 webview/日志/memento；webview 只收 `code + secondsLeft`；导出弹 modal 警告并以 `0600` 写盘；secret 缺失的条目标 `error:'secretMissing'`。
- **配额**：登录态读 `maxAuthenticatorEntries`（`packages/db-host/src/sync/entitlementGate.ts`，fail-closed free=10）；未登录不限；超限弹升级、不展开表单。

### 个人同步（P2 v2）

- **同步对象**：连接 + 分组 + 保存查询 + 查询文件夹四类实体，树内容跨设备完全一致。
- **实体模型**：`SyncEntityType`（4 值）、`SyncEntityRef { type, localId }`、`SyncEntityStore` 适配层；`RecordMapStore`/`PendingMutationStore` 以 typed ref 维护 map/outbox/conflict/revision，双向索引含 type。
- **引用**：跨实体引用统一存 sync `recordId`；目标缺失时保留 unresolved、后续 reconcile，绝不静默归根/未分组。
- **路径口径**：路径字段（`dbPath`/证书/SSH 私钥/`sqliteCommand`/`socketPath`/`connectionUrl` 等）为可同步源值，随 E2EE 密文同步；目标设备「补齐」为本机覆盖，优先级高于源值，仅本机、永不回传、不产 mutation。敏感路径/URL 只进密文，禁入日志/错误/Webview。
- **锁定态零请求**：activation 与 locked 态不产生任何 sync API 请求；session 仅经受控内部 session factory 懒创建；解锁前 `await refreshEntitlement`。
- **自动同步开关**：`devbelt.sync.autoSync`（按机器，默认关闭）。开启后本地 `onChanged(user)`（250ms debounce）与窗口聚焦会自动同步；关闭时仅显式「立即同步 / 拉取 / 推送」触发。**解锁 / 初始化 / 换钥 / 恢复均为纯生命周期动作，不自动同步**；解锁与初始化共用一个入口（`devbelt.syncEntry`：远端有 state→解锁、无→初始化）。命令 `devbelt.toggleAutoSync` 切换，状态栏 tooltip 反映开/关；冲突解决后的后续同步不受开关限制。

### 凭据存储

- 数据库密码、SSH 密码、私钥口令 → VS Code `SecretStorage`。
- 非敏感连接配置（host/port/database/groupId 等）→ `globalState` Memento。

## server

### 启动流程

`createApp()`（组合根）：
1. 创建 Fastify 实例，注册错误处理、CORS、Helmet、Sensible、AJV strict schema。
2. `ensureDatabase()`：确保目标数据库存在（建库必须早于连接池注册）。
3. 注册 MySQL 连接池，初始化 UTC 时区。
4. 初始化 repository 实例。
5. 初始化 service 实例（含 EmailSender 选择、TokenService、AuthService 等）。
6. 启动限流清理等后台任务。
7. 注册路由：/health、auth、me、personal、sync、console（认证/账户/admin/数据）、link-flows、invoice、orders、payment-callback、ai。
8. `await app.ready()`：等待所有插件和路由就绪。
9. `await runMigrations()`：执行 migration（幂等），按 `migrations/index.ts` 顺序（`001`-`024` 已 squash 为基线，当前活跃若干增量；历史版本号见 `LEGACY_MIGRATION_VERSIONS`）。

### 分层

```
routes → services → repositories → MySQL
```

- **Routes**：Fastify 路由，schema 校验（`additionalProperties:false`），调用 service。
- **Services**：业务逻辑、事务编排、权限检查。
- **Repositories**：SQL 查询，行级加锁（`FOR UPDATE`）。
- **Middleware**：`requireAuth` 解析 JWT 并校验 audience/scope/session。

### API 路由

| 前缀 | 功能 |
|---|---|
| `POST /api/auth/*` | 注册、验证邮箱、登录、refresh、logout、改密 |
| `GET /api/db/me` | 当前用户信息和权益 snapshot |
| `GET/DELETE /api/db/personal/devices/*` | 设备列表和撤销 |
| `GET/PUT/POST/DELETE /api/db/sync/*` | 个人 E2E 同步状态、record feed、换钥、恢复、销毁、重置 |
| `POST /api/ai/chat` | AI 代理（parse-and-forward SSE：强制 stream_options、客户端断 abort 上游、事件原样转发）；额度不足 409 |
| `GET /api/ai/usage` | 当月 AI 额度快照（used/reserved/remaining/resetAt） |
| `GET /api/ai/providers` | 模型厂商目录（公开只读、按 IP 限流、5 分钟缓存头；仅启用项，不含密钥） |
| `GET /api/admin/ai/finance/summary?from=&to=` | 区间毛利统计（合计/逐月/每模型；成本取请求流水当时值，收入取订单） |
| `GET /api/admin/ai/users/:id/requests` | 用户 AI 请求流水（计量/积分/当时成本；id 倒序 keyset；不存对话文本，保留 180 天） |
| `GET /api/admin/users/:id/sync-records` | 用户同步记录元数据明细（E2E 加密仅元数据；kind 过滤 + keyset 分页；受限读审计） |
| `GET /api/admin/ai/users/:id/quota` | 用户 AI 数据（双段快照 + grants + 近 6 月用量 + 加油包订单实付聚合） |
| `GET/POST/PATCH /api/admin/ai/providers` | 厂商目录管理（console + CSRF + 幂等键 + 审计 + reason 必填；baseUrl 强制 https） |
| `GET/PATCH /api/admin/ai/billing-settings` | AI 计费设置（激活模型/上游连接/调整系数；Key 只写不读——GET 仅回 configured+尾号） |
| `GET/POST/PATCH /api/admin/ai/model-pricing` | 模型计价表（输入/输出分价 + 统一 token 权重 k；reason 必填进审计） |
| `GET /api/admin/ai/finance?month=` | 财务月报（原始/计费 token、折算成本、实收、毛利） |
| `PATCH /api/admin/users/:id/role` | 管理员角色授予/撤销（防自锁：不可改自己；reason 必填进审计） |

- **AI 月额度（P9）**：`ai_token_usage`（`usage_month` 分桶，reserved_* 预占 + finish 对账；enable-row +
  `FOR UPDATE` 串行化，结算释放用 `LEAST` 防无符号下溢）；`maxAiTokensMonthly` 由权益派生（fail-closed 0，
  0 不表示不限）；上游 401/429/5xx 翻译为 401/429/503，不透传上游原文。

## 套餐/权益执行矩阵

套餐特性分三类执行点，避免"套餐看似生效实则无效"：

| 特性 | 执行点 | 说明 |
|---|---|---|
| `maxSavedConnections` | **客户端** | 新增/导入连接时按 `maxSavedConnections(entitlement)` 拦截 |
| `maxConcurrentConnections` | **客户端** | 打开连接前拦截 |
| `allowConnectionImport/Export` | **客户端** | 导入/导出连接命令拦截 |
| `allowErDiagram` | **客户端** | ER 图命令拦截 |
| `allowedDatabaseTypes` | **客户端（仅同步入站）** | `filterPersonalConnectionsByEntitlement` 过滤跨设备同步记录；**本地新建/使用引擎不限制**（有意设计） |
| `allowDataSync` | **服务端 + 客户端** | 服务端 `syncRecordService.assertRecordQuota` 在写记录时校验（客户端可被绕过）；客户端 `runExplicitSync` 走 `canUseDataSync` 提前提示 |
| `maxConnectionMetas` / `syncStorageBytes` | **服务端** | `assertRecordQuota` 按派生权益强制配额 |
| `maxDevices` | **服务端** | `authService` 登录/设备注册时校验 |
| `maxAiTokensMonthly` | **服务端** | `aiQuotaService` 事务内预占/对账（0 = 拒绝，无"不限"档；超限 409）；客户端仅展示性预检 |

约束：
- 客户端门禁读 `auth.getCachedEntitlement()`；未登录/未拉取时按 Free fail-closed。
- 客户端门禁可被旧版/改内存绕过，**商业约束必须以服务端为准**。
- 本地引擎类型不限 Free 属产品选择；若要限制，需在连接表单/测试处引用 `isDatabaseTypeAllowed`。
