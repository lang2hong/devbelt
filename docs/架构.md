# 架构

## 总体结构

```
┌─────────────────────────────────────────────────────────┐
│                    VS Code Extension                     │
│  ┌──────────┐  ┌──────────┐  ┌───────────────────────┐  │
│  │ db-core   │  │ vscode-  │  │  sync (底层/运行时   │  │
│  │ (driver,  │  │ ext UI,  │  │  /UI 已实现，命令    │  │
│  │  query,   │  │ commands,│  │  已注册，待双机验证)  │  │
│  │  dialect) │  │ trees,   │  │                        │  │
│  │           │  │ webview) │  │                        │  │
│  └──────────┘  └──────────┘  └───────────────────────┘  │
└─────────────────────────┬───────────────────────────────┘
                          │ HTTPS /api
┌─────────────────────────┴───────────────────────────────┐
│                      Fastify Server                      │
│  auth | me | personal | organizations | sync             │
└─────────────────────────┬───────────────────────────────┘
                          │
                     MySQL 8
```

三个包：

| 包 | 路径 | 职责 | 依赖 |
|---|---|---|---|
| db-core | `packages/db-core` | 数据库驱动适配、SQL 方言、连接池、查询执行、元数据、数据操作 | 无 VS Code/服务端依赖 |
| db-host | `packages/db-host` | 宿主无关的编辑器侧逻辑：连接/查询数据层、同步客户端、会话装配、E2EE 同步引擎与密钥生命周期 | db-core |
| vscode-ext | `apps/vscode-ext` | VS Code 生命周期、命令、树视图、Webview、组织 Workspace（同步装配已下沉 db-host） | db-core、db-host |
| server | `apps/server` | 身份认证、权益、设备、组织授权、资源管理、个人同步协议、MySQL 持久化 | 无 VS Code 依赖 |
| db-hostd | `apps/db-hostd` | 把 db-host 暴露为 stdio JSON-RPC 的 sidecar，供非 VS Code 宿主（如未来的 IntelliJ 插件）复用 | db-host、db-core |

## db-hostd

- **协议**：stdin/stdout 逐行 NDJSON JSON-RPC（一请求一响应），入口 `apps/db-hostd/src/index.ts`。
- **方法**：`ping`、`dek.generate|store|load|delete`、`entitlement.allowedEngines`、`sign.requestDigest|stateInput|recordInput|signInput`、`sync.getMe`。
- **端口实现**：`FileSecureStorage`（`SecureStorageLike`，0600 明文文件）与 `FileMemento`；生产桌面宿主应注入各自安全存储。
- **配置**：`DEVKIT_HOSTD_HOME`（默认 `./.db-hostd`）。

## db-host

- **端口（ports）**：`packages/db-host/src/hostTypes.ts` 定义 `SecureStorageLike`（等价 `vscode.SecretStorage` 最小面）等宿主能力接口；各宿主注入实现，db-host 本身零 `vscode` 依赖。
- **连接/查询数据层**：`ConnectionStore`、`QueryStore`（memento + SecretStorage，经端口注入）。
- **同步**：`SyncClient`（HTTP/双 token/重试）、`session`/`sessionFactory`/`runtimeFactory`（会话装配）、`crypto/*`（JCS/HKDF/Ed25519/Argon2 worker）、`e2e/*`（同步引擎、状态/映射/outbox/冲突）。
- **测试**：`apps/vscode-ext/test/` 通过 vitest alias 直接跑 db-host 源码；移动端相关用例的 undici mock 由 `syncFetch` seam 承接。

## db-core

- **Dialect**：MySQL、PostgreSQL、SQLite 三种方言，各自实现 SQL 生成、元数据查询、类型转换。
- **Connection**：统一连接接口，各引擎驱动适配，连接池管理。
- **Query**：SQL 执行、结果集解析、元数据服务（数据库/表/列/索引/视图/例程/事件/触发器/外键）。
- **TableService**：DDL 生成、表结构操作。
- **Export/Import**：CSV、JSON、XML、XLSX、SQL dump 的导入导出。
- **Validation**：标识符校验、SQL 安全确认。
- **有意例外**：`src/sync/`（JCS/签名测试向量）与 `testing` 子路径不属于数据库核心职责，但向量需在 vscode-ext 与 server 两侧共用，故寄居 db-core 经 `./testing` 导出（只含公开向量，无私钥）。属记录在案的有意例外，非职责漂移。

## vscode-ext

### Activation 流程

`extension.ts` 的 `activate()` 按以下顺序初始化（注意：`AuthService` 在 ConnectionManager 之前创建，但其 token 恢复 `auth.init()` 在 ConnectionManager/DbTreeDataProvider 构造之后才 await）：

1. `ConnectionStore`：从 `globalState` 恢复连接和分组，明文凭据迁移到 `SecretStorage`。
2. `AuthService` 实例创建（尚未从 SecretStorage 恢复 token）。
3. `ConnectionManager`、`DbTreeDataProvider`、`QueryExecutor`、`ConnectionContext`、`HistoryStore`、`AuditLogger`、`BackupScheduler`。
4. Webview 初始化（BaseWebView、TableQueryView）。
5. `await auth.init()`：从 SecretStorage 恢复 access/refresh token；若已登录则 `void refreshEntitlement()` 异步拉取 `/api/me`。
6. `syncLoggedInContext(auth)` 设置 `devbelt.loggedIn` 上下文键。权益缓存（`devbelt.sync.cachedEntitlement`）由 `AuthService.getMe()` 统一落盘——init、AccountView/SessionView 打开时都会刷新；本地连接**不走权益门禁**（本地引擎支持只看方言是否注册），权益缓存仅用于个人同步入站 record 过滤（PG 连接同步为 Pro 权益）。
7. 事件订阅：连接变更/DDL 刷新树、配置变更切换语言、文档保存更新保存查询。
8. 创建个人连接树视图 `devbelt.explorer`。
9. 创建组织 Workspace：`OrgClient` → `CredentialVault` → `OrgWorkspace` → `OrgTreeDataProvider` → `devbelt.explorer.organization` 视图。
10. AuthEvent 订阅：logout 时清组织缓存并刷新 `devbelt.loggedIn` 上下文；**当前 login 事件未刷新组织树**，需手动 Refresh（P1 修复）。
11. SQL 补全和 CodeLens 注册。
12. 注册直连命令（openTerminal、designTable、newTableDesigner、serverStatus、ER 图、数据对比、仪表盘、审计日志、连接池、定时备份）。
13. `registerOrgCommands()` 注册组织相关命令。
14. `registerCommands()` 注册所有子模块命令（connection、query、table、database、user、account、group、ddl、search、explorerMenu）。
15. PersonalSyncSession **不在 activate() 中创建**；首次用户调用 Initialize/Unlock 同步命令时懒创建，注册到 `context.subscriptions`。未解锁前不创建 SyncEngine/Coordinator、不发起任何 sync API 请求。

### 命令架构

- `commands/shared.ts` 提供 `makeSub(context)`，统一通过 `vscode.commands.registerCommand` 注册并自动加入 `context.subscriptions`。
- 命令按领域拆分到 `commands/` 目录下各文件：connection、query、table、database、user、account、group、ddl、search、org。
- `test/commands/commandRegistration.test.ts` 自动校验 `package.json` 声明的每条命令都有注册调用点。

### 树视图

- **个人连接树**（`devbelt.explorer`）：`DbTreeDataProvider` 读取 `ConnectionStore.getVisibleTreeData()`，按分组层级展示连接和数据库元数据。节点 contextValue 编码数据库类型，菜单 when 直接匹配，消除时序竞态。
- **组织树**（`devbelt.explorer.organization`）：`OrgTreeDataProvider` 通过 `OrgWorkspace` 读取组织/目录/资源。401 回退个人空间，403/404 清缓存。

### Webview

所有面板继承 `BaseWebView`，使用 Vue 单文件组件，通过 esbuild 打包为单 HTML：

| 面板 | 用途 |

| TableDesignView | 表设计器 |
| ConnectionForm | 新建/编辑连接表单（含测试连接按钮） |
| UserManageView | 数据库实例用户管理 |
| StatusView | 服务器状态 |
| ERDiagramView | ER 图 |
| DataDiffView | 数据对比 |
| DashboardView | 性能仪表盘 |
| AuditLogView | 审计日志 |
| PoolStatusView | 连接池状态 |
| LoginFormView | 登录/注册 |
| AccountView | 账户面板 |
| SessionView | 设备/会话管理 |

### 个人同步（P2 v2）

- **同步对象**：连接 + 分组 + 保存查询 + 查询文件夹四类实体，树内容跨设备完全一致。组织连接（`org:`）及其保存查询不纳入个人同步。
- **实体模型**：`SyncEntityType`（4 值）、`SyncEntityRef { type, localId }`、`SyncEntityStore` 适配层；`RecordMapStore`/`PendingMutationStore` 以 typed ref 维护 map/outbox/conflict/revision，双向索引含 type。
- **引用**：跨实体引用统一存 sync `recordId`；目标缺失时保留 unresolved、后续 reconcile，绝不静默归根/未分组。
- **路径口径**：路径字段（`dbPath`/证书/SSH 私钥/`sqliteCommand`/`socketPath`/`connectionUrl` 等）为可同步源值，随 E2EE 密文同步；目标设备「补齐」为本机覆盖，优先级高于源值，仅本机、永不回传、不产 mutation。敏感路径/URL 只进密文，禁入日志/错误/Webview。
- **锁定态零请求**：activation 与 locked 态不产生任何 sync API 请求；session 仅经受控内部 session factory 懒创建；解锁前 `await refreshEntitlement`。

### 凭据存储

- 数据库密码、SSH 密码、私钥口令 → VS Code `SecretStorage`。
- 组织模板的本机凭据映射 → `CredentialVault`（独立 SecretStorage 键前缀 `devbelt.org.credential.<orgId>.<resourceId>`），不上传服务端。
- 非敏感连接配置（host/port/database/groupId 等）→ `globalState` Memento。

### 国际化

`src/i18n/catalog.ts` 集中管理中英文词条，`l10n(key, vars?)` 查找翻译。`test/i18n/catalog.test.ts` 校验中英文键集一致。

### 打包

- `esbuild.js` 多入口构建：extension 主入口、所有 Webview Vue 页面、Argon2id Worker。
- `.vscodeignore` 排除测试和 fixture，保留 Worker 产物。
- Bundle isolation 测试确保主线程产物不含 `hash-wasm`（Argon2id 只能在 Worker 执行）。

## server

### 启动流程

`createApp()`（组合根）：
1. 创建 Fastify 实例，注册错误处理、CORS、Helmet、Sensible、AJV strict schema。
2. `ensureDatabase()`：确保目标数据库存在（建库必须早于连接池注册）。
3. 注册 MySQL 连接池，初始化 UTC 时区。
4. 初始化 repository 实例。
5. 初始化 service 实例（含 EmailSender 选择、TokenService、AuthService、OrganizationService 等）。
6. 启动限流清理和邀请过期后台任务。
7. 注册路由：/health、auth、me、personal、organizations、organization-invitations、sync、console（认证/账户/组织/admin/数据）、link-flows、invoice、orders、payment-callback。
8. `await app.ready()`：等待所有插件和路由就绪。
9. `await runMigrations()`：执行 migration（幂等），按 `migrations/index.ts` 顺序（当前 24 个，最新 `024_sync_mutation_recovery_time`）。

### 分层

```
routes → services → repositories → MySQL
```

- **Routes**：Fastify 路由，schema 校验（`additionalProperties:false`），调用 service。
- **Services**：业务逻辑、事务编排、权限检查。
- **Repositories**：SQL 查询，行级加锁（`FOR UPDATE`）。
- **Middleware**：`requireAuth` 解析 JWT，`organizationAuth` 解析组织 membership 并检查权限码。

### API 路由

| 前缀 | 功能 |
|---|---|
| `POST /api/auth/*` | 注册、验证邮箱、登录、refresh、logout、改密 |
| `GET /api/me` | 当前用户信息和权益 snapshot |
| `GET/DELETE /api/personal/devices/*` | 设备列表和撤销 |
| `GET/POST /api/organizations` | 列出/创建组织 |
| `GET/PATCH/DELETE /api/organizations/:id/*` | 组织详情、成员、邀请、目录、资源 |
| `POST /api/organization-invitations/:token/accept` | 接受组织邀请（需登录：membership.userId 须等于当前登录用户） |
| `GET/PUT/POST/DELETE /api/sync/*` | 个人 E2E 同步状态、record feed、换钥、恢复、销毁、重置 |

### 组织权限

- 角色：`admin`（可管理成员/目录/资源/关闭组织）、`member`（只读）。
- 组织写事务按 `organization → subscription → membership → invitation → folder → resource` 加锁。
- 资源更新使用乐观锁 `(id, organization_id, version)`，冲突返回 `409 RESOURCE_VERSION_CONFLICT`。
- 资源内容严格闭合（服务端）：
  - 连接模板：`databaseType`（服务端仅校验非空字符串；扩展端据其选择引擎，未知值 fail-closed）、`host`、`port`、`database`、`username`、`ssl`（`mode`、`rejectUnauthorized`，扩展端据此推导 `useSSL` 并把 `rejectUnauthorized` 透传到连接层）；拒绝密码、SSH、证书、本机路径等字段。
  - 查询：`sql`、可选 `dialect`（`mysql`/`postgresql`/`sqlite`）。
- 客户端：
  - `toSavedConnection()` 由 `databaseType` 映射引擎，未知值拒绝。
  - SSL `rejectUnauthorized` 已传递到 `ConnectionConfig`。
  - 组织菜单按 `devbelt.orgRole` 隐藏 member 的写操作入口。
  - 登录成功后 `AuthEvent('login')` 触发组织工作区重选默认组织。

## 套餐/权益执行矩阵

套餐特性分三类执行点，避免"套餐看似生效实则无效"：

| 特性 | 执行点 | 说明 |
|---|---|---|
| `maxSavedConnections` | **客户端** | 新增/导入连接时按 `maxSavedConnections(entitlement)` 拦截 |
| `maxConcurrentConnections` | **客户端** | 打开连接前拦截 |
| `allowConnectionImport/Export` | **客户端** | 导入/导出连接命令拦截 |
| `allowErDiagram` | **客户端** | ER 图命令拦截 |
| `allowedDatabaseTypes` | **客户端（仅同步入站）** | `filterPersonalConnectionsByEntitlement` 过滤跨设备同步记录；**本地新建/使用引擎不限制**（有意设计） |
| `allowDataSync` | **服务端 + 客户端** | 服务端 `syncRecordService.assertRecordQuota` 在写记录时校验（客户端可被绕过）；客户端 `runExplicitSync` 走 `canUseDataSync` 提前提示 |
| `maxConnectionMetas` / `syncStorageBytes` | **服务端** | `assertRecordQuota` 按派生权益强制配额 |
| `maxDevices` | **服务端** | `authService` 登录/设备注册时校验 |

约束：
- 客户端门禁读 `auth.getCachedEntitlement()`；未登录/未拉取时按 Free fail-closed。
- 客户端门禁可被旧版/改内存绕过，**商业约束必须以服务端为准**。
- 本地引擎类型不限 Free 属产品选择；若要限制，需在连接表单/测试处引用 `isDatabaseTypeAllowed`。
