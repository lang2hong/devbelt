# P7.1 — PostgreSQL 多 schema 与多库

> 状态：draft v1（B1a/B1b 已实现，B2 待实施）。本文档是这条功能线的唯一权威规格：
> 先讲清楚给用户什么，再讲设计与切片。
>
> 定位：P7（Redis 客户端）发布后的 **SQL 侧增量**。对既有 PG 单 schema 连接零回归——
> 未显式给出 schema 时，对象名不加限定，仍交连接 `search_path` 解析。

## 一、这个阶段要做什么

补齐 PostgreSQL 在 DevBelt 里最明显的两处能力缺口：

1. **多 schema**：能浏览并操作该库下的**多个 schema**，而不只是 `public`（或连接默认 schema）。
2. **多库**（B2）：能浏览该连接可见的**全部数据库**。

MySQL 一个连接可 `USE` 多库、每「库」下直接是对象；PG 是「库 → schema → 对象」两层。
此前 DevBelt 只把 PG 的默认 schema 当作对象作用域，其他 schema 里的表既看不到、也不能操作。

## 二、用户能做什么

- 树里的 PG 库节点下先出 **Schema 层**（`public` 置顶，`information_schema`/`pg_*` 等系统 schema 不列），
  每个 schema 下再是表/视图/函数/事件分类。
- 在**任意 schema** 上执行写/DDL/导出/数据编辑；对象一律按 `"schema"."table"` 限定。
- （B2）列出该连接可见的全部库；点开某库按需建立会话，在某个库上执行查询、浏览对象。

## 三、设计

- **schema 是独立维度**：`DbTreeNode.schema`（节点）、元数据方言方法 `(database?, schema?)`、
  `qualifyTable(dbType, table, database?, schema?)`。PG **只认 schema 通道**（`database` 是库名，不是 schema）；
  MySQL/SQLite 仍走 `database` 槽（`db.table`）。
- **写/DDL/导出/数据编辑** 全部按 schema 限定：`TableService`（建/删/改/复制/列/索引/外键/触发器/视图）、
  `DataService`（增删改）、`dumpSql`/`buildInsertSql`、设计器。
- 默认 schema = `conn.schema || 'public'`；系统 schema 不列。
- PG 的结构/数据**跨库对比维持不支持**（一个连接绑定一个库），沿用既有明确拒绝而非给误导结果。

### 约束与决策（B2）

- 无权限库不列：`SELECT datname FROM pg_database WHERE datallowconn AND NOT datistemplate AND has_database_privilege(datname,'CONNECT')`。
- 按库懒建会话（复用同一 SSH 隧道）；同一连接额外会话上限 **4 + LRU**；会话缓存 key **含 database**（`connId\u0000库名`）。
- SSH 隧道改为**引用计数**：多库会话共享一条隧道，失败/关闭只释放自己的引用，归零才关。
- 会话键语义：**PG 节点 `database` = 库名、`schema` = 命名空间**（B1a 曾把 schema 放进 database 槽，B2 纠正）；限定名用 `schema`，选会话用 `database`。
- 衍生库会话**不计入**用户并发连接数门禁（`openCount` 按 `connId` 去重）。
- 提供「在该库上执行」（查询编辑器/结果面板绑定节点所在库），**不提供 `USE` 语义**。
- 结构对比/同步维持 PG 不支持跨库。

## 六、已知限制

- PG 的结构/数据跨库对比不支持：`compareSchema`/`syncDatabase`/`compareData` 对 PG 均明确拒绝（一个连接绑定一个库）。
- **A6：未使用 SQL 参数绑定**。schema/表名走 `validateIdent` 白名单 + 字符串字面量（拒绝单引号，安全），代价是含空格/点/引号的合法 schema 被列表过滤、无法操作。**放宽白名单之前，必须先改成参数绑定**。
- 本地无 PostgreSQL，schema 真机路径未在本机验证（依赖 D28 CI / 用户环境）。
