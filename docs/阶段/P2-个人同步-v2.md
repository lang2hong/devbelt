# P2 — 个人同步 v2：全量同步

> 本文是 P2 的一次范围修订。相对 `P2-个人同步-v1.md`，唯一变化是**同步对象从「仅连接」扩展为「连接 + 分组 + 保存查询 + 查询文件夹」，路径字段改为跨设备同步**；协议层、密码学原语、生命周期状态机、验收矩阵框架保持不变（以本文为准，冲突处本文覆盖 v1）。

## 背景与范围变更

| 事项 | v1 原状 | v2 现决定 |
|---|---|---|
| 同步对象 | 仅个人连接配置 | **连接 + 分组 + 保存查询 + 查询文件夹**（树内容完全一致） |
| `groupId` | 不同步 | **同步** |
| 保存查询 / 查询文件夹 | 不同步 | **同步** |
| 本机路径字段 | 不进入 payload | **同步**（见 D1） |
| 隐私边界 | 路径不入密文 | 同一账号跨设备无隐私边界；内容随 E2EE 密文同步 |

---

## 一、已确认决策（产品方拍板）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 路径字段 | **跨设备同步源配置 + 本机覆盖**。连接记录中的路径字段（`dbPath`/`caPath`/`clientCertPath`/`clientKeyPath`/`sshPrivateKeyPath`/`sqliteCommand`/`socketPath`/`connectionUrl`/`useConnectionString`）是可同步的规范源值，随 E2EE 密文同步至所有已解锁设备；用户在普通连接编辑中修改它们是源配置修改，会产生同步 mutation。风险已由产品方确认接受：`connectionUrl` 可能内嵌密码、`sqliteCommand` 可能带参数。敏感路径/URL 只能进入 E2EE 密文，禁止出现在日志、错误详情或 Webview 消息中。 |
| D2 | 查询文件夹 | **跟随连接、扁平**：`QueryFolder` 增加 `connId` 归属，无 `parentId` 层级；保存查询已有 `connId`+`folderId`。 |
| D3 | 跨实体引用 | **统一用 sync `recordId`**；目标记录未到达/pending/tombstone/冲突时保留 unresolved 引用，后续页/轮次 reconcile；绝不静默归根或未分组。 |
| D4 | 兼容 | **不做旧数据迁移**（开发阶段，无真实同步数据）；旧 map/payload 按新结构重建。`QueryFolder` 新增 `connId` 字段：旧无 `connId` 的文件夹作为不可同步记录 tombstone 处理（开发阶段无真实用户数据，不保守复制）。 |

## 二、同步实体与 payload 类型

明文 payload 带 `type` 判别：`connection | group | queryFolder | query`。

| type | 本地实体 | 字段 | 引用字段（存 **recordId**） |
|---|---|---|---|
| `connection` | SavedConnection | 全量连接字段（含 `groupId`、全部路径字段、按引擎白名单） | `groupId` → group recordId |
| `group` | ConnectionGroup | `name`、`parentId` | `parentId` → 父 group recordId（根 undefined） |
| `queryFolder` | QueryFolder（**新增 `connId`**） | `name`、`connId` | `connId` → connection recordId |
| `query` | SavedQuery | `name`、`sql`、`connId`、`database`、`folderId` | `connId`→connection、`folderId`→queryFolder recordId |

- 编码：本地 id → recordId（经 RecordMapStore 反向索引）；目标无 recordId 时记 unresolved，后续 reconcile。
- 解码/应用：recordId → 本地 id；目标映射不存在时**保留 unresolved、不归根**。
- 保持：`dbType` 归一 engine、未知类型 fail-closed、`additionalProperties:false`、SQLite 禁 TCP/SSL/SSH 字段。

## 三、删除与级联语义

| 事件 | 行为 |
|---|---|
| 连接 tombstone | 级联 tombstone 其下查询与文件夹 |
| 分组 tombstone | 其下连接 `groupId`→undefined（移未分组），连接本身不动 |
| 文件夹 tombstone | 其下查询 `folderId`→undefined（移根级，与现有 `removeQueryFolder` 一致） |

- 级联/变迁**由客户端产生**：删除父实体时，客户端 mutator 同批生成子实体 update/tombstone 并进入 outbox、按顺序重放、崩溃后幂等收敛。服务端因 E2EE 密文不可见，不维护跨实体外键。

## 四、类型化基础设施

- `SyncEntityType`（4 值）、`SyncEntityRef { type, localId }`、`SyncEntityStore` 适配层。
- `RecordMapStore` entry 改为 `{ type, localId, recordVersion, revision, status }`；双向索引含 type。
- `PendingMutation` / 去重键 / 冲突条目 / revision 比较全改用 typed ref。

## 五、payload 上限与错误

- record ciphertext 仍 ≤256 KiB；查询 SQL 上限 64 KiB UTF-8，编码前校验，超限报用户可读错误。
- 客户端在 `sealRecord` 前对 `query` 类型的 `sql` 字段按 UTF-8 字节长度（非 `.length`，中文/Emoji 为多字节）校验：超过 65536 字节时 fail-closed 抛「SQL 内容超过 64KiB 上限」，不等到服务端 256 KiB ciphertext 报 413/400。

## 六、路径字段的口径（D1/B3 冲突裁定）

- **源配置（同步值）**：连接记录中的路径字段是规范源值，随 E2EE 密文跨设备同步；普通连接编辑修改它们产生同步 mutation。
- **本机覆盖（B3 补齐值）**：目标设备发现同步路径不存在/不可读时，用户「补齐」填写的值是该设备的本地覆盖，**优先于源值**，仅存本机、永不回传，不修改同步 record、不更新 revision、不产生出站 mutation、不触发同步事件。
- **优先级**：有效建连配置 = 本机覆盖优先，否则同步源值。删除本机覆盖后恢复使用同步源值，后者继续随远端更新。
- 适用范围：`connectionUrl`、`useConnectionString`、`dbPath`、证书路径、SSH 私钥路径、`sqliteCommand`、`socketPath` 均遵循此优先级。
- 阶段 A：codec 同步完整路径源值，提供基于有效配置的路径校验/建连拒绝 API，但不提供补齐 UI。阶段 B：实现本地覆盖存储与补齐 UI；补齐不触发同步事件或 mutation。

# 阶段 A —— 全量同步引擎 + 接线

## A0 · 规格与数据模型裁决（本文即权威，文档先行）

内容即上文「一～五」：决策 + 数据模型 + 删除级联 + 类型化基础设施 + 上限。

## A1 · 类型化基础设施

- 落地 `SyncEntityType` / `SyncEntityRef` / `SyncEntityStore` 适配层。
- `RecordMapStore` entry 改 `{ type, localId, recordVersion, revision, status }`；双向索引含 type。
- `PendingMutation` / 去重键 / 冲突条目 / revision 比较改 typed ref。
- **验收**：四类型双射、跨类型不变量。

## A2 · 关系安全的 codec

- 四类 discriminated payload；引用转 recordId；未知类型/额外字段/缺失或非法引用 fail-closed；维持 SQLite TCP/SSL/SSH 字段限制。
- `encodeRecordPayload` 对 `query` 类型 `sql` 字段 UTF-8 字节长度 > 65536 时 fail-closed 抛「SQL 内容超过 64KiB 上限」。
- **验收**：四类型 round-trip、引用正反解析、畸形输入拒绝、SQL 超限拒绝。

## A3 · entity store adapter + apply

- 单实体 create/update/delete/idempotency；unresolved reference 队列 + reconcile；父删级联按「三」的事务语义（客户端 mutator 同批生成、outbox 顺序重放、崩溃幂等收敛）。
- **apply 拓扑序**：按依赖方向 `group → connection → queryFolder → query`（group 被 connection 引用、connection 被 folder/query 引用、folder 被 query 引用）；批内引用先于被依赖者到达则立即翻译，否则入 unresolved 队列，后续 reconcile 收敛。
- **unresolved 不静默落根**：unresolved `parentRef`/`groupId`/`connId`/`folderId` 不置为 `undefined`（不落根/不未分组），保留 unresolved 标记；A 阶段数据层留钩子，B2 树展示做虚拟分组。
- **环检测（安全必需）**：apply remote group 前校验 `parentId !== id`、沿 parentId walk 最多 32 步遇环 fail-closed（terminal）；嵌套深度 > 8 层 fail-closed 防病理嵌套。
- **验收**：四类型 CRUD + tombstone + 幂等 + 级联 + unresolved 收敛 + 环/自指/超深拒绝全覆盖。

## A4 · 全类型 mutator + 事件接线

- 四类对账产 mutation；`ConnectionStore` 与 `QueryStore` 事件都触发 reconcile；每实体一条 in-flight mutation。
- **source 透传**：所有 entity 写方法接受 `source: ChangeSource`；sync 路径 `source='sync'` 不触发用户侧 `onChanged`（避免回环），本地编辑 `source='user'` 触发。
- **验收**：四类新建/编辑/软删产正确 mutation；空变更不产；不重复；source 透传区分 sync/用户。

## A5 · composition root（无 UI）

- 惰性 session 工厂、logout lock/dispose、窗口聚焦触发（受自动同步开关约束，见 B2）、unlock 前 `await refreshEntitlement`；activation/locked 态**绝不发 sync 请求**；**不注册**未实现 UI 命令（同步命令到 B1 才注册）。
- **验收**：activation 零请求；session 懒建；dispose 干净。

## 阶段 A 附加 · 路径校验 API（不含 UI）

- `validateConnectionPaths(conn)` 可查询 API + `ConnectionManager` 建连硬拒绝（路径缺失/无效即拒建，不静默降级）。
- 树 warning 图标 / tooltip / 补齐表单属阶段 B。

# 阶段 B —— UI 闭环 + 双设备验收

## B1 · 初始化 / 解锁最小闭环

- SMP → Argon2id Worker → init/unlock；init 201 后持久化 snapshot+DEK → unlock。**解锁/初始化本身不产生同步**（纯生命周期动作）；随后是否同步由自动同步开关或显式命令决定。
- 解锁与初始化是**同一个用户入口**「启用同步」：探测远端——有 state→解锁、无 state→初始化（`devbelt.syncEntry`）；面板只显示这一颗按钮，不再按本机 `localEpoch` 分列「初始化/解锁」。
- **pull 游标（`changeSequence`）**：解锁**不采用远端 head**，而是保留本机最后应用的游标（补拉「离线期间他设备上传」的变更）；全新设备无本地快照时从 `0` 拉全量历史。服务端 `changeSequence` 是用户级全局单调序列、永不重置（§7.3），故保留本机值既不回退也不漏新记录。
- 错误提示（SMP 错/GCM 失败/状态损坏）；恢复码一次性展示+确认；pendingCleanup 引导。
- 此时才注册面向用户的同步命令。
- **验收**：初始化后重启可解锁；错误 SMP 不启动；恢复码只展示一次。

## B2 · coordinator + 树刷新 + 状态栏

- `scheduleNow`/指数退避/stalled 停止；窗口聚焦触发；成功刷树；状态栏 setContext。
- **自动同步开关（按机器）**：`devbelt.sync.autoSync`，**默认关闭**。关闭时不自动同步——本地变更 `onChanged`、窗口聚焦均不触发；仅显式「立即同步 / 拉取 / 推送」触发。开启后仅恢复「本地变更 / 窗口聚焦」自动触发；**解锁/初始化/换钥/恢复均不补同步**（纯生命周期动作）。开关经配置项 + 命令 `devbelt.toggleAutoSync` + ⋯菜单切换，状态栏 tooltip 反映开/关。冲突解决后的 `scheduleNow` 属显式动作后续，不受开关限制。
- **验收**：首次 pull 刷树；退避/阈值；焦点触发；关闭开关后本地新建/编辑连接不产生任何 sync 请求，手动命令仍可用。

## B3 · needsConfig UI

- 树 warning 图标 + tooltip（缺什么路径）；点击补齐全对话框；补齐前禁止建连；补齐值为本机覆盖，仅存本地、永不回传、不产生 mutation（见「六」）。
- **验收**：路径缺失连接不可建连、有标记；补齐后可建连且不回传出站；删除本机覆盖后恢复同步源值。

## B4 · 冲突持久化 + 冲突 UI

- outbox `conflict` 字段 + `replaceMutation`；Use Local / Use Remote / Cancel 三态原子迁移。
- **验收**：并发改同连接产生冲突；三操作各自收敛。

## B5 · 生命周期 UI（换钥/恢复/销毁/重置）

- 四流程 QuickPick/Webview；destroy/reset 走 `reconcileEpochTransition` cleanup intent 幂等。
- **验收**：换钥后他设备新 SMP 解锁；恢复码轮换；destroy 后新 epoch；reset token 一次性/限流。

## B6 · 双设备安装版验证

- 两 Profile 同账号按验收矩阵验证（连接/分组/查询/路径/needsConfig/冲突/SMP/恢复/销毁/重置/跨窗口轮换）。
- **验收**：矩阵全 pass。
