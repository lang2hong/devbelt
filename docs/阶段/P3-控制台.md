# P3 — 控制台（Console UI）

## 目标

提供浏览器访问的管理控制台，覆盖用户账户设置、组织管理、平台运营后台和支付入口。复用现有 auth/device API，不引入独立管理会话。

## 范围

P3 新建独立前端包 `packages/console-ui`，由 Fastify 服务端同源托管 `/console/*`（与 API 同域，避免跨域/CORS 复杂度）。

### 用户侧（登录用户可访问）

- 账户概览：邮箱、显示名、订阅套餐、到期时间。
- 个人同步状态：是否已初始化、最近同步时间、记录数/字节配额使用。
- 设备管理：查看已登录设备列表、查看设备信息（平台/名称/最后活跃时间）、远程撤销设备。
- 修改登录密码（调用现有 `/api/auth/change-password`）。
- 修改同步口令入口（跳转到扩展内 UI——浏览器控制台不做 E2EE 密钥操作，密钥操作只在 VS Code 扩展内进行）。
- 订单历史、发票下载。

### 组织管理侧（org admin 可访问）

- 查看所属组织列表，切换组织。
- 成员列表：查看成员邮箱、角色、加入时间。
- 邀请成员：输入邮箱 + 选择角色（admin/member）→ 发邀请邮件（调用现有邀请 API）。
- 移除成员、变更成员角色（admin 操作，最后一个 admin 不可降级）。
- 关闭组织（二次确认）。
- 目录与资源浏览（只读查看；编辑仍在 VS Code 扩展内完成，v1 不做浏览器内 SQL 编辑器）。

### 平台运营侧（平台管理员）

- 用户查询：按邮箱/ID 搜索、查看订阅、禁用/启用用户。
- 订阅管理：手动授予/撤销订阅、调整到期时间。
- 审计日志：登录、支付、同步销毁、组织操作日志。
- 限流与系统配置查看。

### 支付入口

- 套餐选择页（Free/Pro/Team）。
- 微信/支付宝支付下单（调用 P4 后端 API）。
- 支付结果回跳页。

## 技术栈选择

2026-09 裁定：采用 **Vue 3 + Vite + TypeScript**（复用 vscode-ext webview 既有栈：vue 3.5 / vite 6 / vitest / @vitejs/plugin-vue）。原「建议 React + Vite」作废——仓库现有 webview 已用 Vue，复用同一前端范式风险更低，避免给 monorepo 引入第二套 UI 框架。复用现有 REST API 与同域 cookie/token 鉴权，不新增 GraphQL 或 WebSocket。

## 服务端改动

- `packages/server` 新增 `/console/*` 静态资源托管（Vite build 产物）。
- `/console/api/me`（或复用现有 `/api/me`）返回当前用户和角色信息。
- 平台管理员鉴权：新增 `requireAdmin` 中间件，校验 `users.role = 'admin'`（需要 user 表新增 role 字段）。
- 审计日志表（新增 migration）记录登录、支付、组织、同步管理操作。
- 不新增密钥管理或 E2EE 相关接口（密钥操作保留在 VS Code 扩展内）。

## 邮件跳转页（一次性链接落地）

SMTP 邮件里的一键链接（由服务端 `smtpEmailSender` 用 `SMTP_BASE_URL` 前缀拼出）要在 console-ui 里落成三个**独立页面**。路径约定已固定，两侧须同步（改任何一端都要改另一端）：

| 路径 | 用途 | 鉴权 | 落地接口 |
|---|---|---|---|
| `/verify-email?token=` | 邮箱验证 | **匿名** | `POST /api/auth/email-verifications/:token/confirm` |
| `/accept-invitation?token=` | 接受组织邀请 | 需登录 | `POST /api/organization-invitations/:token/accept` |
| `/sync-reset?token=` | 同步重置确认 | 需登录 | `POST /api/sync/reset-after-loss`（body 带 resetToken） |

要点：

- 三者是**根路径**的公开跳转页，与 `/console/*` 管理后台分开托管（verify-email 无会话、不能塞进需登录的后台）。
- **鉴权是最大的坑**：只有 `verify-email` 是匿名的。`accept-invitation` 要求「当前登录用户的 `membership.userId` 等于邀请目标」（`route/invitations.ts` 在 auth 作用域下）；`sync-reset-after-loss` 同样需要登录。因此这两个页面**做不到点链接即完成**——clic 后若无登录态，须先跳 console 登录再回跳处理。
- **落地顺序**：第一步只做 `verify-email`（匿名、无会话、链路最简）；邀请 / 重置在 console-ui 具备登录态后接上，或暂时邮件里弱化这两个按钮。
- `SMTP_BASE_URL`：dev 指向 console-ui 本地 dev 端口，prod 指向 console-ui 部署域名；该变量只决定链接前缀，不改变服务端行为。

已知文档不一致：`docs/架构.md` 的 API 表把 `POST /api/organization-invitations/:token/accept` 标为「公共端点，无需登录」，与实际代码（auth 作用域 + `authUserId`）不符，P3 落地时一并更正。

## 不在 P3 范围

- 浏览器内 SQL 编辑器。
- 浏览器内数据库连接（直连用户数据库）。
- 资源内容在线编辑（P3 只读浏览组织资源，编辑仍在 VS Code）。
- 团队协作实时编辑、注释。
- 多因素认证（MFA）。

## 前置依赖

- P2 个人同步 v1 完成（服务端协议稳定、密钥生命周期有双设备验证）。
- 服务端用户角色字段（区分普通用户/平台管理员）。
- 审计日志表结构设计。

## 验收

- 同源访问 `/console/` 登录后看到账户页面。
- 普通用户只能访问用户侧页面，无法访问组织管理其他组织、无法访问运营后台。
- 组织 admin 能管理自己的组织成员。
- 平台管理员能进入运营后台，普通用户访问 `/console/admin` 返回 403。
- 登出后清除 cookie/session。
- 不处理任何 E2EE 密钥或密文（浏览器控制台不接触 DEK/SMP/恢复码/签名私钥）。
