## 已确定的边界

1. v2 是 Greenfield：不迁移旧用户、订阅、设备、refresh token、同步密文、连接、日志、支付回调或限流配置；不做双写、兼容层或旧客户端支持。
2. 每位注册用户建立一个 personal org、admin membership、Free 订阅和一个有效席位。Team 是真正的多席位 team org。
3. `organizations.owner_user_id` 是商业 Owner 的唯一权威；membership 只有 `admin` 与 `member`。
4. 私人设备、连接、同步和历史仍属于 user。用户处于多个组织时，私人额度取其有效席位套餐的最高值，不叠加。
5. 团队共享资源属于 organization。首期允许连接模板、查询、文件夹，采用服务端授权和服务端静态加密；绝不保存数据库密码、SSH 密码或 SSH 私钥。
6. Team 种子价格目前为 ¥20/月、¥200/年，包含 5 个席位，额外席位同价。这只是待商业确认的默认 seed，不代表最终对外定价。

## S3（已完成）

按可验证边界分三批推进，以下各批均已落地并接入运行时。

### S3a：新增 v2 领域与仓储（已完成）

1. 在 `domain/enums.ts` 增加组织、成员、席位、订单、资源和权限枚举。
2. 在 `domain/entities.ts` 增加 Organization、Membership、Seat、Order、OrganizationResource、OrganizationResourcePermission、OrganizationAuditLog。
3. 在 `repository/interfaces.ts` 增加六组对应 repository 接口。
4. 在 `repository/mysql/` 增加对应 MySQL repository。
5. 在 `test/helpers/fakeRepos.ts` 增加内存 fake，并为每个 repository 增加单测。
6. 本批是纯增量：不改现有 `User`、`Plan`、`Subscription`、现有 repo、service、route 或 `app.ts`。完成后必须保持旧 586 个测试全绿。

### S3b：切换业务模型（已完成）

1. 将 User 移除 `planCode`，补 `displayName`；将 Plan 切换到 per-seat/per-user/org 字段；将 Subscription 归属 organization。
2. 改造 AuthService：注册必须原子创建 user、personal org、membership、Free subscription 和 seat。
3. 改造套餐与配额 policy：按有效席位求用户个人最高额度，按 organization 求共享额度。
4. 改造 device、refresh token、connection metadata、sync repo/service 使用 v2 列名及语义。
5. 实现组织、成员、席位、共享资源、权限和组织审计 service/route；改写 payment/webhook 处理 `seat_delta`。
6. 同步改写 fakeRepos、testApp、service 和 route 测试；完成前允许中间工作区短暂不通过编译，但不得提交中间状态。

### S3c：运行时切换与旧代码移除（已完成）

1. 仅当 S3b 的 repo/service/route 全部适配后，`app.ts` 才能由 `initSchema` 切到 `runMigrations`。
2. 删除已被 v2 替代的实体、接口、repo、维护/流量/限流/旧审计路径和对应测试。
3. 对一个全新的空数据库运行 migration、套餐 seed 和 bootstrap，再执行服务端集成测试。
4. 任何真实数据库清空、部署、或生产切换均为高风险操作，须单独确认并先创建可恢复快照。
