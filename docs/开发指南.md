# 开发指南

## 环境要求

- Node.js 20 或 22
- pnpm（通过 `corepack enable` 启用）
- VS Code
- Docker 和 MySQL 8（服务端集成测试需要）

## 安装

```bash
pnpm install
pnpm build
```

## 验证命令

全量：

```bash
pnpm typecheck     # 三个包 tsc --noEmit
pnpm test          # 三个包全部测试
```

包级：

```bash
pnpm -C packages/db-core test
pnpm -C apps/vscode-ext test
pnpm -C apps/vscode-ext typecheck
pnpm -C apps/server test
pnpm -C apps/server typecheck
```

扩展打包：

```bash
pnpm -C apps/vscode-ext package   # 生成 .vsix
node apps/vscode-ext/esbuild.js  # 仅构建（不打包）
```

服务端集成测试需要设置 `MYSQL_TEST_URL`，测试数据库名必须包含 `test` 或 `verify`。

## 调试

### 扩展

1. VS Code 打开仓库根目录。
2. 选择 "Run Extension" 调试配置。
3. F5 启动 Extension Development Host。

### 服务端

```bash
cd apps/server
cp .env.example .env
docker compose up -d    # 启动 MySQL
pnpm dev                # 启动服务端（tsx watch）
```

默认服务端地址由 esbuild 构建时注入（见 `esbuild.js` 的 `define`）。

## 代码规范

- 数据库驱动与查询逻辑放在 `db-core`，不得依赖 VS Code 或服务端领域。
- VS Code 生命周期、UI、本地状态放在 `vscode-ext`。
- 身份、授权、协议和持久化放在 `server`。
- 用户可见文案必须走 `i18n/catalog.ts`，中英文键集保持一致。
- 不得在主线程引入 `hash-wasm` 或直接执行 Argon2id；KDF 必须通过 `deriveKekSmpInWorker()` 在 Worker 中执行。
- 修改阶段规格、API、权限或协议时更新对应阶段文档并补充测试。
- 新增命令必须同时出现在 `package.json` 的 `contributes.commands` 和命令注册调用点；`commandRegistration.test.ts` 会自动核查。
- 改动扩展入口、命令、菜单、视图或打包内容后，必须生成 VSIX 并在干净 Profile 做安装 smoke test。

## 项目结构

```
apps/                      # 可部署单元
├── server/                # Fastify 服务：认证、组织、同步 API、MySQL 持久化、静态托管
│   ── src/
│       ├── route/         # Fastify 路由
│       ├── service/       # 业务逻辑
│       ├── repository/    # MySQL 数据访问
│       ├── middleware/    # 认证、组织授权、限流、错误处理
│       └── db.ts          # 数据库初始化和 migration
├── vscode-ext/            # VS Code 宿主：命令注册、树视图、webview、组织 Workspace
│   ── src/
│       ├── commands/      # 命令注册（按领域分文件）
│       ├── connection/    # 连接存储、管理器、上下文
│       ├── result/        # Webview 面板
│       ├── tree/          # 树数据提供者和节点
│       ├── sync/          # 认证、同步客户端、加密、E2E 协议（部分 dormant）
│       ├── org/           # 组织 Workspace、客户端、凭据、缓存
│       ├── completion/    # SQL 补全、CodeLens
│       ├── i18n/          # 国际化 catalog
│       ├── schedule/      # 定时备份
│       ├── terminal/      # 终端集成
│       ├── history/       # 查询历史
│       └── utils/         # 事件总线、审计日志、ID 生成
├── db-ui/                 # /db 控制台（Vue 3 + Vite）
└── e2e/                   # Playwright 端到端
packages/                  # 仅被多方 import 的库
└── db-core/               # 数据库驱动、方言、连接、查询、同步密码学（宿主无关）
    └── src/
        ├── connection/    # 驱动适配、连接池、类型转换
        ├── dialect/       # MySQL/PG/SQLite 方言与 SQL 生成
        ├── query/         # 查询执行、元数据、结果解析
        └── utils/         # 校验、标识符
```

## 测试结构

- `apps/vscode-ext/test/`：按源码镜像组织。重点测试文件：
  - `commands/commandRegistration.test.ts`：命令/视图注册完整性自动核查。
  - `sync/bundleIsolation.test.ts`：主线程 bundle 不含 Argon2id 执行体。
  - `sync/crypto/smpKdf.test.ts`：Worker KDF fail-closed 行为。
  - `sync/e2e/`：同步引擎、状态存储、outbox、映射的单元测试。
- `packages/db-core/test/`：方言、查询、元数据服务测试；MySQL 集成测试在无 MySQL 环境下 skip。
- `apps/server/test/`：路由、service、repository 测试。
