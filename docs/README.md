# DevBelt 文档中心

本目录按“产品 → 架构 → 开发 → 发布与运维 → 工作包”的线性顺序组织。第一次阅读建议从上往下；查资料可直接跳到对应表格。

## 推荐阅读顺序

1. [产品介绍](产品介绍.md) — 产品是什么、当前能做什么、哪些还在开发中。
2. [套餐边界](套餐边界.md) — Free/Pro 的能力与额度边界、执行点、运营修改方式。
3. [版本路线图](版本路线图.md) — 已发布版本之后的版本线、功能批次与发布策略。
4. [架构](架构.md) — 代码结构、包职责、关键运行流程（只记录当前代码事实）。
5. [开发指南](开发指南.md) — 环境搭建、构建、测试、调试、打包。
6. [发布与运维](发布与运维.md) — 发布检查、安装版 smoke、部署/回滚、运行手册、未完成门禁、验收矩阵、migration 回滚。
7. [工作包](工作包/README.md) — 单一功能规格与状态。

## 按角色阅读

| 角色 | 建议阅读 |
|---|---|
| 新用户 / 产品 | 产品介绍 → 版本路线图 |
| 新开发者 | 产品介绍 → 架构 → 开发指南 → 对应工作包 |
| 发布负责人 | 版本路线图 → 发布与运维（§1–§8） |
| 运维 | 开发指南 → 发布与运维（§3–§9） |
| 安全 / 评审 | 架构 → 发布与运维 §8（P6 安全评审） |
| QA | 发布与运维 §7/§8 → 对应工作包 |

## 文档规则

- **一事一处**：README 只做索引，不重复状态。
- **当前事实**只写在产品介绍与架构。
- **未来方案**只写在版本路线图与工作包。
- **发布、验收、部署、回滚、运行**只写在发布与运维。
- **功能实现细节**只写在工作包。
- 已删除或被替代的内容不再新建“历史”目录；需要追溯时使用 git 历史。
- 新增文档必须在本页登记，并标明唯一职责与负责人。
