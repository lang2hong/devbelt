# 数据库迁移回滚

迁移是**前向**的：`migrations/index.ts` 只执行 `up`。结构/数据变更若需回滚，按下表执行手工 SQL。
执行前先备份（`mysqldump`），并在低峰期操作；回滚 SQL 一般**只针对对应迁移引入的增量**。

| 迁移 | 回滚 SQL | 说明 |
|---|---|---|
| `006_redis_engine` | 见下 | 仅移除本迁移追加的 `redis` 权益；只增不减的放宽，通常无需回滚 |
| `007_audit_query_indexes` | 见下 | 删除三个审计查询索引；纯查询优化，通常无需回滚 |

## 006_redis_engine

移除本迁移给 free/pro 的 `allowedDatabaseTypes` 追加的 `redis`：

```sql
UPDATE plan_feature_values v
  JOIN plans p ON p.id = v.plan_id
  JOIN plan_feature_defs d ON d.id = v.feature_def_id
   SET v.value_json = JSON_REMOVE(
         v.value_json,
         JSON_UNQUOTE(JSON_SEARCH(v.value_json, 'one', 'redis'))
       )
 WHERE d.feature_key = 'allowedDatabaseTypes'
   AND p.code IN ('free', 'pro')
   AND JSON_VALID(v.value_json)
   AND JSON_TYPE(v.value_json) = 'ARRAY'
   AND JSON_CONTAINS(v.value_json, JSON_QUOTE('redis'));
```

注意：`JSON_SEARCH(..., 'one', ...)` 只移除**首个** `redis`。若数组中可能有重复项，重复执行本 SQL 直到
`JSON_CONTAINS` 不再命中（幂等收敛）。

回滚后需同步回退迁移账本（否则再次部署会跳过 006）：

```sql
DELETE FROM schema_migrations WHERE version = '006_redis_engine';
```

> 账本表名以 `apps/server/src/repository/mysql/migrate.ts` 实际实现为准。

## 007_audit_query_indexes

删除本迁移为审计查询补的 `(过滤列, id)` 复合索引，并回退账本：

```sql
ALTER TABLE audit_events DROP INDEX idx_audit_actor_id;
ALTER TABLE audit_events DROP INDEX idx_audit_type_id;
ALTER TABLE audit_events DROP INDEX idx_audit_target_id;
DELETE FROM schema_migrations WHERE version = '007_audit_query_indexes';
```

回滚后审计列表按过滤列分页会重新走 filesort（功能不受影响，仅性能回退）。

## 012_ai_credits_billing

积分化 + 多模型计费：每模型倍率列 / 成本测算占比列 / 请求流水表 / 月账本原始 token 列。

```sql
ALTER TABLE ai_model_pricing DROP COLUMN multiplier_override;
ALTER TABLE ai_billing_settings DROP COLUMN typical_output_ratio;
ALTER TABLE ai_token_usage DROP COLUMN raw_prompt_tokens, DROP COLUMN raw_completion_tokens;
DROP TABLE ai_request_log;
DELETE FROM schema_migrations WHERE version = '012_ai_credits_billing';
```

注意：回滚后财务月报的"原始用量"退回计费 token 口径（012 前的既有近似）；请求流水删除后
区间统计只剩单月近似口径。回滚 012 前建议先停服（结算路径会写 `ai_request_log`）。

## 011_ai_model_pricing

- 目的：AI 计费引擎——模型计价表 + 单行计费设置（统一 token 口径 / 上游连接 / 调整系数，
  管理后台可配置；`upstream_api_key` 只写不读，任何 GET 不回明文）。
- 变更：新建表 `ai_model_pricing`（model 唯一；分/1M 单价、权重覆盖）与 `ai_billing_settings`
  （单行 id=1：激活模型、上游 baseUrl/api_key、全局系数）。无预置数据（全空 = 回退 env，行为与现状一致）。
- 回滚 SQL：

```sql
DROP TABLE ai_model_pricing;
DROP TABLE ai_billing_settings;
DELETE FROM schema_migrations WHERE version = '011_ai_model_pricing';
```

回滚后：计费回到 1:1 合计口径（k=1、系数 1）、上游连接回退 env；`ai_token_usage` 已按加权口径
入账的当月数据不回改（口径切换以切换点为界）。

## 010_ai_providers

- 目的：AI 模型厂商目录（自带 Key 模式的预设：厂商 / baseUrl / 模型，管理后台维护）。

  预置 8 家（OpenAI/阿里百炼/DeepSeek/智谱/小米 MiMo/Moonshot/硅基流动/MiniMax，
  `ON DUPLICATE KEY` 幂等，不覆盖运营已改行）。
- 回滚 SQL：

```sql
DROP TABLE ai_providers;
DELETE FROM schema_migrations WHERE version = '010_ai_providers';
```

## 009_ai_topup

回滚前**先导出 `ai_quota_grants` 与 `orders`（purpose='topup'）的资金关联数据**（退款/审计凭据不可再生）。

```sql
DROP TABLE ai_quota_grants;
DROP TABLE ai_topup_skus;
ALTER TABLE orders DROP CHECK chk_orders_topup;
ALTER TABLE orders DROP CHECK chk_orders_purpose;
ALTER TABLE orders DROP KEY idx_orders_purpose;
ALTER TABLE orders DROP CHECK chk_orders_channel;
ALTER TABLE orders ADD CONSTRAINT chk_orders_channel CHECK (channel IN ('wechat', 'alipay'));
ALTER TABLE orders DROP COLUMN sku_code;
ALTER TABLE orders DROP COLUMN purpose;
ALTER TABLE orders MODIFY COLUMN plan_code VARCHAR(32) NOT NULL;
DELETE FROM schema_migrations WHERE version = '009_ai_topup';
```

回滚后：月额度计量回退为单段（`ai_token_usage.reserved_*` 预占/对账不变）；已发放加油包余额与
已售订单历史一并丢失（保留在导出文件中），P9.1b/c（收银台/管理后台/客户端）未交付不受影响。
