# 管理后台架构

本文说明平台运营后台和组织管理后台的领域边界。完整交付范围、支付/审计契约、实施顺序和验收以[V3 完整交付实施规格](V3完整交付实施规格.md)为唯一基线；当前系统事实以[实施规格](实施规格.md)为准。

当前服务端已实现认证、设备、当前用户、个人权益、组织、成员、邀请、资源和个人同步 API；当前没有平台管理员身份、平台管理 API、浏览器管理应用和审计设施。VS Code 扩展只实现了组织资源 Workspace。

## 1. 结论

系统需要浏览器管理后台，但不能把平台运营和组织管理混为同一种权限：

- 平台运营后台服务平台管理员，处理跨用户、跨组织的运营事务。
- 组织管理后台服务组织 `admin`，只能处理所属组织的成员和协作空间。
- VS Code 扩展服务数据库工作流和组织资源协作，不承担完整运营管理界面。

推荐使用一个独立 Web 应用，按路由、API 和服务端中间件拆成两个隔离区域：

| 区域 | 浏览器路由 | 访问者 | 数据范围 |
|---|---|---|---|
| 平台运营 | `/console/admin/*` | `platform_admin` | 全平台运营元数据 |
| 组织管理 | `/console/organizations/:organizationId/*` | 该组织 active `admin` | 单个 `organizationId` |
| VS Code 组织 Workspace | 扩展树视图和命令 | 该组织 active member/admin | 目录、资源、连接模板和本地凭据映射 |

一个用户可以同时是平台管理员和某些组织的管理员；两种权限独立判定，不相互推导。

### 1.1 交付约束

实施者以本文作为后台功能的唯一设计输入，并遵守以下边界：

- 不把后台工作拆成与后台无直接关系的服务端重构、安全整改或历史兼容工作；服务端变更只限于平台角色、审计、`/api/admin/*`、组织后台缺失 DTO，以及同源控制台托管所直接需要的能力。
- 不恢复已删除的 `packages/admin-ui`，不沿用其 token、路由、接口或部署假设；新应用固定为 `packages/console-ui`。
- 不新增第二套认证或管理会话；浏览器按 §3.3 复用现有设备登录协议。
- 未写入本文的页面、接口、字段、权限或运营动作不在首期范围；需要新增时先更新本文，再实施。
- 每个工作包必须连同所属测试和文档同步交付，不以“前端可访问”替代服务端授权与审计验收。

### 1.2 实施者交接清单

后台按以下顺序推进；前一项完成并通过对应验收后，才开始依赖它的下一项：

| 工作包 | 交付物 | 直接依赖 | 完成标志 |
|---|---|---|---|
| A. 平台基础 | `010_platform_admins`、`011_admin_audit_events`、平台角色 repository/service、首位管理员受控引导 | 现有用户与 MySQL migration 框架 | migration、角色授予/撤销与最后管理员保护测试通过 |
| B. 平台 API | `requirePlatformAdmin`、step-up、平台只读/写 API、审计追加与查询 | A | `/api/admin/*` 的未认证、非管理员、管理员和写失败场景均有 route/integration 测试 |
| C. 组织后台补齐 | 组织概览 DTO、仅 admin 可见的成员邮箱 DTO | 现有组织 API 与授权 | 普通 member 无法获得邮箱或管理写权限，admin 可完成成员/邀请管理 |
| D. 浏览器控制台 | `packages/console-ui`、登录、平台只读页、组织成员/邀请页、写操作确认与原因 | B、C | 深链接、会话失效、路由守卫与 API 越权测试通过 |
| E. 同源交付 | `@fastify/static`、`/console/` fallback、构建和部署产物流程 | D | `/console/*` 深链接可加载，`/api/*` 和 `/health` 不被 fallback 覆盖 |

本文件列出的后台范围必须与[V3 完整交付实施规格](V3完整交付实施规格.md)一致。支付、订单、退款和人工运营的首期交付以主规格第 5 节至第 10 节为准；流量分析、多因素认证和组织恢复仍按本文件 §10 排除。

## 2. 当前实现与目标状态

### 2.1 当前实现

- 服务端已注册认证、设备、当前用户、个人、组织、邀请和同步路由。
- 组织角色只有 `admin` 和 `member`，组织 `admin` 可管理成员、角色、邀请、目录和资源。
- VS Code 扩展已实现组织 Workspace、共享查询和连接模板；本地凭据只保存在用户本机的 `SecretStorage`。
- 当前没有平台管理员身份、平台管理 API、审计事件表、浏览器管理应用和支付能力。
- 当前扩展没有组织成员、邀请或组织设置的管理界面。
- 服务端当前没有注册静态文件插件，无法托管前端产物。

### 2.2 目标状态

- 管理后台作为独立前端包 `packages/console-ui` 构建，产物由服务端以 `@fastify/static` 在 `/console/` 同源托管；外层反向代理只负责 TLS 与转发，不单独管理前端文件。同源部署使 CORS 与 CSRF 面最小，也无需扩展当前单值 `CORS_ORIGIN`。
- 平台运营区域和组织管理区域共享登录与组件，但使用不同的路由守卫、API 前缀和服务端授权中间件。
- 平台 API 不接受组织 membership 作为授权依据；组织 API 不接受平台角色作为绕过组织数据范围的理由。
- 所有管理写操作记录可查询的审计事件。

### 2.3 实施前置项

以下能力当前不存在，必须在对应方案落地前先补齐：

| 前置项 | 说明 |
|---|---|
| `@fastify/static` 依赖与注册 | 同源托管管理后台产物；当前 `packages/server` 未依赖该插件，也未注册任何静态路由 |
| 平台角色与审计表 | 任何平台 API 的前提，见 §4 |
| 平台授权中间件 | `requirePlatformAdmin` 与 `/api/admin/*` 分区，见 §3.2 |

## 3. 身份、授权与会话

### 3.1 身份类型

| 身份 | 存储与来源 | 授权作用域 | 不能获得的权限 |
|---|---|---|---|
| 普通用户 | `users` | 本人个人空间 | 平台数据、未加入组织的数据 |
| 组织 `member` | `organization_memberships` active membership | 一个组织的只读协作空间 | 成员管理、邀请、组织设置、写资源 |
| 组织 `admin` | `organization_memberships` active membership | 一个组织的管理与协作空间 | 平台用户、其他组织、成员的个人数据 |
| `platform_admin` | 独立平台角色授予记录 | 平台运营 API | 用户密码、refresh token 原文、个人同步明文与密钥、组织本地凭据 |

`platform_admin` 不应通过邮箱域名、前端隐藏菜单、组织角色或客户端传入字段隐式推断。服务端必须从受控角色记录读取它。首位平台管理员通过运维侧一次性引导流程写入，不提供公开注册入口；授予和撤销都必须留下审计事件。

### 3.2 授权顺序

组织 API 的固定顺序：

1. 验证 access token 与用户状态。
2. 从 URL 读取 `organizationId`，不信任前端当前选中组织。
3. 查询组织状态和 active membership。
4. 根据 organization role 判定 permission code。
5. 在事务内重新锁定组织、订阅、成员和受影响资源后写入。

平台 API 的固定顺序：

1. 验证 access token 与用户状态。
2. 查询受控平台角色记录，要求 active `platform_admin`。
3. 对写操作校验 step-up 重认证状态（见 §3.3）。
4. 对目标用户、组织或订阅执行最小数据查询。
5. 在事务内执行写操作并写入审计事件。

错误口径固定为：

- 未认证或 token 失效返回 `401 UNAUTHORIZED`。
- 已认证但不是平台管理员，访问 `/api/admin/*` 返回 `403 PLATFORM_ADMIN_REQUIRED`；响应不包含目标对象是否存在的信息。
- 平台管理员访问不存在的目标对象返回 `404`，因为此时调用者已被授权。
- 组织作用域继续沿用现有防枚举口径：组织不存在、已关闭或调用者不是 active member 时统一 `404 ORGANIZATION_NOT_FOUND`。

前端路由守卫只改善体验，不能替代服务端授权。

### 3.3 会话模型

管理后台复用现有认证协议：`POST /api/auth/login`、`/api/auth/refresh`、`/api/auth/logout`，不引入第二套会话系统。

现有登录体要求 `deviceKey`、`devicePlatform`、`deviceName`、`clientVersion`（`packages/server/src/route/schemas.ts`）。浏览器按以下约定满足：

- 首次访问生成一个 256-bit 随机 `deviceKey`，持久化在浏览器本地存储，后续登录与刷新复用同一个值；
- `devicePlatform` 固定为 `web`，`deviceName` 使用浏览器/主机可读标识，`clientVersion` 用管理后台版本号。

由此管理会话就是一台普通设备：出现在 `/api/personal/devices`，可被用户自行撤销，遵循同一套 refresh token 轮换与复用检测。这是期望行为，不是缺陷。个人 Free 套餐 `maxDevices = 0` 表示不限设备数，因此不会因为多开浏览器被配额挡住。

其余会话要求：

- 管理员 token 不得从 URL query 或 hash 读取、写入或跳转传递。URL 会进入历史、日志、Referer 和截图。
- access token 只保存在内存；refresh token 保存在 `sessionStorage`，关闭标签页即失效，不做"记住我"。
- 前端不缓存平台角色作为授权依据，每次进入平台区域都由服务端判定。
- 初期管理员在后台手动登录。若未来需要从扩展单点跳转，服务端必须签发一次性、短时效、单次消费的换取码。
- 管理后台除 localhost 开发环境外必须经 HTTPS 访问；TLS 在反向代理层终止，`TRUST_PROXY` 需与实际代理跳数一致（当前默认 1）。

平台写操作的额外保护（禁用账号、调整订阅、授予或撤销平台角色）：

- 要求 step-up 重认证：在写请求前的短窗口内重新校验当前密码，窗口过期返回 `PLATFORM_REAUTH_REQUIRED`；
- 要求二次确认与原因输入；
- 支持可选的平台管理 IP 白名单，未配置时不启用。

多因素认证不属于首期；step-up 首期即"重新输入当前密码"。

## 4. 数据模型（规划）

新增两张表，接在现有 `009_personal_sync` 之后。项目未发布，不需要兼容旧库。列命名沿用 `snake_case`，时间为 UTC `DATETIME(3)`，主键为 `BIGINT UNSIGNED AUTO_INCREMENT`。

### 4.1 `010_platform_admins`

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | 主键 |
| `user_id` | `BIGINT UNSIGNED` | 指向 `users`，唯一 |
| `status` | `VARCHAR` | `active` 或 `revoked` |
| `granted_by_user_id` | `BIGINT UNSIGNED NULL` | 授予人；引导流程为 `NULL` |
| `granted_time` | `DATETIME(3)` | 授予时间 |
| `revoked_by_user_id` | `BIGINT UNSIGNED NULL` | 撤销人 |
| `revoked_time` | `DATETIME(3) NULL` | 撤销时间 |
| `reason` | `VARCHAR NULL` | 授予或撤销原因 |

索引：`user_id` 唯一键；`(status, user_id)`。

授权判定只接受 `status = 'active'`。撤销为软删除，保留历史。

### 4.2 `011_admin_audit_events`

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | 主键 |
| `event_time` | `DATETIME(3)` | 事件时间 |
| `actor_user_id` | `BIGINT UNSIGNED` | 操作者 |
| `actor_scope` | `VARCHAR` | `platform` 或 `organization` |
| `action` | `VARCHAR` | 动作标识，例如 `user.status.update` |
| `target_type` | `VARCHAR` | `user`、`organization`、`subscription`、`platform_admin` 等 |
| `target_id` | `VARCHAR NULL` | 目标标识 |
| `organization_id` | `BIGINT UNSIGNED NULL` | 组织作用域事件填写 |
| `result` | `VARCHAR` | `success` 或 `failure` |
| `reason` | `VARCHAR NULL` | 操作原因 |
| `changed_fields` | `JSON NULL` | 仅字段名与摘要，不含秘密值 |
| `request_id` | `VARCHAR NULL` | 请求关联 ID |

索引：`(event_time, id)` 用于稳定分页；`(target_type, target_id, event_time)`；`(actor_user_id, event_time)`；`(organization_id, event_time)`。

表只追加。后台不提供修改或删除入口。保留期与归档策略在实现时确定，删除只能由运维侧按保留期批量执行。

实现这两个 migration 时，必须同步更新实施规格的 migration 顺序表、核心表清单和错误码目录。

## 5. 功能边界

### 5.1 平台运营后台

首期只读优先，随后再开放受审计的写操作。

| 模块 | 首期能力 | 写操作前置条件 |
|---|---|---|
| 用户 | 查询用户状态、邮箱验证状态、注册时间、设备数和订阅摘要 | 禁用与恢复账号须填原因、step-up 重认证、二次确认和审计 |
| 组织 | 查询组织状态、套餐、席位、资源用量和成员摘要 | 关闭组织须填原因、审计，且不得绕过最后管理员保护 |
| 套餐与订阅 | 查询套餐、个人与组织订阅及权益快照 | 修改须事务化、审计并明确生效时间 |
| 审计 | 查询管理操作、账号状态和订阅变更事件 | 只读；事件只追加 |
| 平台角色 | 查询平台管理员列表与授予历史 | 授予与撤销须填原因、step-up 重认证和审计 |

账号禁用是可逆操作。组织关闭在首期不可逆：关闭会移除 invited membership 并撤销待处理邀请，重新开放需要另行定义成员与邀请的恢复语义，不属于首期。

流量与配额分析不属于首期。当前唯一相关的 `rate_limit_entries` 是限流窗口计数且会被周期清理，不能作为流量底座；该模块需要先引入独立的聚合指标表。

平台后台不显示或导出密码、token、refresh token hash、邮箱验证 token hash、个人同步 ciphertext、nonce、签名、恢复材料、组织资源正文或本地凭据映射。

### 5.2 组织管理后台

只面向该组织的 active `admin`。

| 模块 | 能力 | 已有服务端基础 |
|---|---|---|
| 概览 | 组织名称、状态、套餐、席位和资源用量 | 部分，需要新增聚合读取 DTO |
| 设置 | 修改名称、关闭组织 | 有组织更新与关闭 API |
| 成员 | 列成员、调整角色、移除成员 | 有 API，成员 DTO 需扩展 |
| 邀请 | 创建、查看、撤销邀请 | 有 API |
| 协作资源 | 管理目录、查询、连接模板 | 有 API；扩展已覆盖主要资源工作流 |

成员列表当前只返回 `membershipId`、`displayName`、`role`、`status` 和 `joinedTime`，同名成员无法区分。

邮箱按 admin-only 返回：现有成员列表使用 `member.read`，而普通 `member` 也持有该权限，直接给 DTO 加 `email` 会把邮箱暴露给全体成员。因此服务端只在调用者锁内角色为 `admin` 时附加 `email` 字段，`member` 得到的响应保持现状。成员 DTO 不包含个人订阅、设备、个人同步状态或任何个人连接信息。

组织管理后台不得读取成员的个人连接、个人同步状态、设备、个人订阅或 `SecretStorage` 内容。连接模板只保存允许的公共连接参数；每个成员自己的用户名、密码和 SSH 凭据仍只保存在本机。

### 5.3 VS Code 扩展边界

扩展保留以下职责：

- 浏览和使用组织资源；
- 打开共享查询、连接模板和本地数据库会话；
- 将组织连接模板与本地 `SecretStorage` 凭据映射组合为临时连接；
- 为组织 admin 提供“打开组织管理页”的外链入口。

扩展不复制浏览器管理后台的用户、套餐、订阅、审计和组织成员管理页面，避免同一套管理逻辑在 webview 与浏览器应用中重复实现。

## 6. Web 与 API 设计

### 6.1 路由分区

前端统一挂在 `/console` 下，只需要一个构建 base 和一条 history fallback，不与 `/health`、`/api` 或未来的根路径冲突：

```text
/console/login
/console/admin/users
/console/admin/organizations
/console/admin/plans
/console/admin/subscriptions
/console/admin/audit
/console/admin/platform-admins

/console/organizations/:organizationId
/console/organizations/:organizationId/settings
/console/organizations/:organizationId/members
/console/organizations/:organizationId/invitations
/console/organizations/:organizationId/resources
```

托管要求：`packages/console-ui` 构建 base 固定为 `/console/`，产物输出到服务端静态目录，由 `@fastify/static` 挂载；`/console/*` 的未知子路径回落到管理应用入口 HTML；`/api/*` 和 `/health` 不参与回落。静态资源使用带哈希的文件名长缓存，入口 HTML 不缓存。

前端进入组织区域时必须先调用组织详情 API。服务端返回 `404 ORGANIZATION_NOT_FOUND` 或 `403` 时清理该页面缓存并跳转无权页，不根据页面 URL 推断数据权限。

### 6.2 API 分区

平台 API 使用 `/api/admin/*`：

```text
GET   /api/admin/users
GET   /api/admin/users/:userId
PATCH /api/admin/users/:userId/status
GET   /api/admin/organizations
GET   /api/admin/organizations/:organizationId
POST  /api/admin/organizations/:organizationId/close
GET   /api/admin/plans
GET   /api/admin/subscriptions
GET   /api/admin/audit-events
GET   /api/admin/platform-admins
POST  /api/admin/platform-admins
POST  /api/admin/platform-admins/:userId/revoke
```

这些路由全部通过 `requirePlatformAdmin` 中间件，写操作额外要求 step-up 状态。禁止把平台查询附加到 `/api/me`、`/api/personal/*` 或 `/api/organizations/*`。

组织管理继续使用现有 `/api/organizations/:organizationId/*` API。新增组织概览或用量接口时保持同一 URL scope，并继续通过组织授权中间件与 permission code 保护。

所有列表 API 使用稳定排序、分页上限、明确过滤字段和最小 DTO；默认不返回敏感字段或大正文。

### 6.3 错误码

新增：

- `PLATFORM_ADMIN_REQUIRED`：已认证但不是 active 平台管理员。
- `PLATFORM_REAUTH_REQUIRED`：平台写操作缺少有效 step-up 重认证。
- `PLATFORM_ACCESS_BLOCKED`：请求来源不在已配置的平台管理 IP 白名单内。

组织作用域继续使用现有 `ORGANIZATION_NOT_FOUND`、`FORBIDDEN`、`ORGANIZATION_ADMIN_REQUIRED` 等错误码。实现时同步补入实施规格的错误目录。

## 7. 审计与可观测性

管理审计事件至少包含：事件 ID、时间、操作者用户 ID、操作者作用域、动作、目标类型、目标 ID、组织 ID（如适用）、结果、原因和请求关联 ID。

审计事件不得包含密码、token、验证码、组织资源正文、个人同步密文、恢复码、私钥、完整请求体或完整响应体。更新动作只记录字段名和变更前后摘要，不记录秘密值。

后台指标只展示聚合值。按用户或组织钻取时返回运营所需的最小元数据，不把审计或日志当作数据导出接口。

## 8. 界面语言

管理后台首期只提供中文界面，与当前主要使用场景一致。文案集中在与扩展一致的 catalog 结构中，不散落在组件内，便于后续补充英文而无需重构页面。

## 9. 实施顺序与验收

### 9.1 服务端基础

1. 实现 `010_platform_admins`、`011_admin_audit_events` 及引导与撤销流程。
2. 实现 `requirePlatformAdmin`、step-up 校验、可选 IP 白名单和 `/api/admin/*` 路由分区。
3. 实现审计事件追加写入、查询索引和保留策略。
4. 为组织管理补足概览 DTO，并按 admin-only 规则附加成员邮箱；复用现有组织授权与事务规则。
5. 同步更新实施规格的 migration 表、核心表清单、API 表和错误码目录。

平台角色与账号状态的安全不变量：

- 不得撤销最后一位 active 平台管理员；允许自我撤销，但必须仍有其他 active 平台管理员。
- 授予对象必须是 active 且邮箱已验证的用户。
- 禁用账号必须填原因、写审计，并同时撤销该用户的 refresh token；恢复账号不恢复任何旧会话，用户须重新登录。
- 不得禁用最后一位平台管理员，也不得禁用任意 active 组织的唯一 active admin（需先转移组织管理员）。

审计写入规则：

- 成功审计与业务变更同事务；审计写入失败则业务回滚。
- 已认证的管理写操作在业务失败回滚后，另开事务写失败审计。
- 未认证扫描与普通越权只进安全日志，不写管理审计表。
- 首期审计范围为平台写操作，以及组织设置、成员和邀请变更；普通目录与资源编辑不审计。

验收：普通用户、组织 member 和组织 admin 均不能访问 `/api/admin/*`；平台管理员不能通过平台 API 获得秘密材料；跨组织请求不能读取或修改目标组织；平台写操作缺少 step-up 时被拒绝并留下失败审计。

### 9.2 Web 管理应用

1. 建立 `packages/console-ui`（Vue 3 + TypeScript + Vite + Vue Router），构建 base 固定为 `/console/`。
2. 在服务端新增并注册 `@fastify/static`，挂载 `/console/`，配置 SPA 回落。
3. 先实现登录、会话失效处理、平台只读页面和组织成员与邀请页面。
4. 再实现受审计的写操作、确认对话框、原因输入、分页、筛选和错误处理。
5. 构建与部署清理旧产物，避免已删除路由和资源残留。

验收：未登录无法读取管理页面数据；路由守卫和 API 都拒绝越权；刷新页面不通过 URL 暴露 token；`/console/*` 深链接直接访问可正确加载；`/health` 与 `/api/*` 不被 fallback 影响。

### 9.3 扩展端衔接

1. 保持组织 Workspace 的资源操作与浏览器后台无状态耦合。
2. 为组织 admin 增加打开对应组织管理页的入口，只传组织标识，不传 access token。
3. 登录态变化、成员角色变更或组织关闭后清理组织缓存并重新拉取。

验收：扩展不向 URL 传 token；组织 member 不显示管理入口且服务端拒绝；组织资源与本地凭据隔离保持不变。

### 9.4 部署

1. 调整 `packages/server/deploy.sh`：构建并上传 `console-ui` 产物。当前脚本会删除远端静态目录且不上传任何前端产物，必须在托管落地时同步修订。
2. 定义静态资源缓存与版本化策略。

## 10. 非目标

以下内容不属于本架构首期：

- 发票；
- 自动续费；
- 流量与配额分析报表；
- 组织关闭后的恢复流程；
- 为组织资源增加字段级 ACL 或内容加密；
- 让平台管理员解密个人同步数据或读取本地凭据；
- 在 VS Code webview 复制完整平台运营后台；
- 通过隐藏菜单、前端布尔字段或 URL token 实现管理员授权；
- 多因素认证（step-up 首期只用当前密码）；
- 与设备会话解耦的独立管理会话系统。
