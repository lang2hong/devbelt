# DB Client — 开发文档

面向贡献者：如何在本地搭建、构建、调试、测试与发布本仓库。

## 环境要求

- Node.js ≥ 18（推荐 20+）
- pnpm（Node ≥ 18 自带 corepack，或 `npm i -g pnpm`）
- VS Code（用于扩展调试）

## 仓库结构

```
packages/
├── db-core/     # 纯连接/查询/元数据层（无 vscode 依赖，可独立测试）
├── vscode-ext/  # VS Code 扩展（webview 查询/设计/ER、树、命令、补全、i18n、同步客户端）
├── server/      # 云同步后端（Fastify + MySQL + JWT）
└── admin-ui/    # Vue 3 管理后台（独立包，构建产物输出到 server/public 供静态托管）
```

## 安装

```bash
pnpm install
```

## 构建

```bash
# 构建全部
pnpm build

# 单独构建 db-core（vscode-ext 依赖其 dist 产物，改动 db-core 后需重建）
cd packages/db-core && pnpm build

# vscode-ext
cd packages/vscode-ext
node esbuild.js          # 编译扩展主进程
cd webview && npx vite build   # 编译 webview
```

## 类型检查

```bash
pnpm typecheck
# 或单包（三包都用 tsconfig.test.json，把 test/ 一并纳入检查）
cd packages/db-core   && npx tsc --noEmit -p tsconfig.test.json
cd packages/vscode-ext && npx tsc --noEmit -p tsconfig.test.json
cd packages/server    && npx tsc --noEmit -p tsconfig.test.json
```

## 测试

```bash
pnpm test
# 单包
cd packages/db-core    && npx vitest run
cd packages/server     && npx vitest run
cd packages/vscode-ext && npx vitest run   # 注意：其 test 脚本会先跑 vite build
```

测试框架为 [Vitest](https://vitest.dev)，测试文件命名 `*.test.ts`，位于各包 `test/` 目录。三包均有测试套件（db-core / server / vscode-ext）。

> `vscode-ext` 的 `pnpm test` 会先执行 `vite build` 再跑 vitest，因为部分测试依赖 webview 产物。只想跑单测时直接用 `npx vitest run`。

## 扩展调试（F5）

1. 用 VS Code 打开仓库根目录。
2. 打开 `packages/vscode-ext` 的调试配置（Launch Extension）。
3. 按 F5 启动 Extension Development Host。

## Webview 开发

```bash
cd packages/vscode-ext
node esbuild.js --watch          # 主进程热编译
cd webview && npx vite build --watch   # webview 热编译
```

## 后端本地运行

```bash
cd packages/server
cp .env.example .env   # 填入 MYSQL_PASSWORD 与 JWT_SECRET
docker compose up -d   # 启动 MySQL + server
```

## 发布

### 打包 vsix

```bash
cd packages/vscode-ext
pnpm build
pnpm package   # 等价于 npx vsce package --no-dependencies
```

产物：`packages/vscode-ext/vscode-db-client-*.vsix`。

> 注意：vsce 打包的是 `packages/vscode-ext/README.md`（市场版）。根目录 `README.md` 与 `docs/` 属于仓库文档，不进入 vsix。

### 发布到 VS Code 市场

1. 在 `packages/vscode-ext/package.json` 中：
   - 将 `publisher` 从 `local` 改为你的发布者 ID
   - 补充 `repository`、`homepage`、`bugs` 字段
   - 更新 `version`
2. 复查 `README.md`（市场版）与 `CHANGELOG.md`。
3. 登录市场并发布：
   ```bash
   cd packages/vscode-ext
   npx vsce login <publisher>
   npx vsce publish
   ```

## 代码约定

- **分层**：业务/驱动逻辑放 db-core（纯层），UI/命令/生命周期放 vscode-ext，服务端逻辑放 server。
- **类型**：严格模式，`tsc --noEmit` 必须通过。
- **安全**：SQL 一律走 `validateIdent` + 方言 `wrap` + 参数化/`escape`；不要在 webview 后端手工拼接转义。
- **国际化**：用户可见文案走 `i18n`（l10n），不要硬编码中文/英文。
- **测试**：纯逻辑（补全引擎、SQL 安全、加密、传输、server service/policy）必须补单测。server 层用 `test/helpers/fakeRepos.ts` 的内存假仓储，不依赖真实 MySQL。
- **驱动返回值**：不要直接 `!!` 驱动返回的布尔字段。MySQL 驱动会把 `0`/`1` 变成字符串 `"0"`/`"1"`，`!!"0"` 为真。一律走 `toBool`（`db-core/src/utils/coerce.ts`）。

## 贡献流程

1. Fork 并创建功能分支。
2. 实现 + 补测试，跑通 `typecheck` 与 `test`。
3. 提交 PR，说明改动与验证方式。
