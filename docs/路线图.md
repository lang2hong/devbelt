每个阶段有一份完整的阶段文档，承载该阶段的规格、实现顺序、测试与验收，路线图不再重复实现细节：

## 当前阶段顺序

| 阶段 | 目标 | 完成定义 |
|---|---|---|
| P0 | 确认扩展在 VSIX 安装后核心本地路径可用 | Clean Profile 安装 + MySQL/SQLite 全流程可跑，命令/菜单/视图零空注册，无明文密码泄露 |
| P1 | 登录后组织功能完整可用 | 登录自动刷新组织树、组织查询 CRUD、模板临时连接、权限菜单一致、登出清理干净 |
| P2 | 同账号多设备安全同步个人数据（连接、分组、保存查询、查询文件夹，树完全一致） | 双设备双 Profile 验收矩阵全通过，协议修复、引擎+接线、初始化/解锁 UI、自动同步、冲突解决、改密码/恢复/销毁/重置闭环 |
| P3 | 浏览器 Console UI 管理后台 | 账户、设备、组织管理、运营后台同源托管 |
| P4 | 支付闭环 | 微信/支付宝回调、订单状态机、权益生效、对账 |

## 阶段依赖

P1 依赖 P0 安装版可用。P2 依赖 P1 的账户/认证/权益基础。P3 依赖 P2 服务端协议稳定。P4 依赖 P3 可管理订单与权益。

## 文档事实规则

- 阶段文档是该阶段的唯一权威规格，路线图不再描述实现细节。
- 架构文档仅记录当前代码事实，不描述未来方案。
- 产品介绍仅记录用户可见能力状态，不承载设计。
- 静态注册测试不等于安装版可用；Clean Profile VSIX smoke test 是 P0 发布的必要条件。
