## 阶段依赖

P2 依赖 P0 的账户/认证/权益基础。P3 依赖 P2 服务端协议稳定。P4 依赖 P3 可管理订单与权益。
P7（引擎接缝+Redis）在 P6 之后，依赖现有 SQL 连接/凭据体系但不依赖同步。
P7.1（PG 多 schema/多库）是 P7 发布后的 SQL 侧增量，只动 PG 数据层与树，不引入新引擎。
P8（ES）依赖 P7 引入的 EngineKind/ConnectionSession 判别联合，复用同一接缝。
P9（AI）是跨引擎的横向能力接缝，不新增引擎、不改 ConnectionSession；依赖现有 schema 元数据与查询错误面（QueryError）、DDL 执行闸门（`confirmSqlExecution`/`ensureWritable`，表设计器经 TableDesignView 私有 mutate 组 SQL 后再走该 gate）、权益/SecretStorage/BaseWebView 体系，可与 P7/P8 并行推进但不改动既有接缝。

## 文档事实规则

- 阶段文档是该阶段的唯一权威规格，路线图不再描述实现细节。
- 架构文档仅记录当前代码事实，不描述未来方案。
- 产品介绍仅记录用户可见能力状态，不承载设计。
- 静态注册测试不等于安装版可用；Clean Profile VSIX smoke test 是 P0 发布的必要条件。
